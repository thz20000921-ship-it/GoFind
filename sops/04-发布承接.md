# 04 · 发布承接

## ① 本步只读

- `workspaces/<业务>/INDEX.md`，定位唯一当前版本。
- `workspaces/<业务>/PROFILE.md`，核对账号、平台和已确认承诺。
- 本文件 `sops/04-发布承接.md`。
- 规则文件到此为止，禁止乱翻 `docs/`、`knowledge/`。
- 只读取该版本成品、逐页单据、授权、账号映射和已有回执。
- 直接复用已审核成品，不重新选题。

## ② 本步只写

- 只写 `workspaces/<业务>/publish/`。
- 本次提交放 `publish/<note-id>/`。
- 真实提交回执保存为 receipt.md。
- 平台截图和提交预览保存在同一提交目录。
- production、INDEX、PROFILE 和旧回执保持只读。

## ③ 执行步骤

1. 核对本次版本、账号和发布条件。
   - 从 INDEX 顶部取得成品位置，逐项核对图片、标题和正文。
   - 读 visual-review.md，确认逐页有具体所见且结论全为「能上」。
   - 核对图片文件名、页序与单据 SHA256。
   - 缺逐页单据或仍有待看/要重做页，停下交人工验收。
   - 查已有 receipt，已确认发布的同版本不重复提交。
   - 平台状态不明时先查原账号，禁止直接重试。
   ```powershell
   $publish = "workspaces/<业务>/publish/<note-id>"
   New-Item -ItemType Directory -Force -Path $publish | Out-Null
   ego-browser skill
   ```
2. 用已有 ego 环境准备提交预览。
   - 按工具指南打开指定站点和当前账号。
   - 核对登录者的账号标识，不能用别人的主页代替。
   - 核对本次获准版本、账号、平台、动作和公开范围。
   - 按最终页序上传原图，确认平台缩略图和数量。
   - 逐字填入已审核标题与正文。
   - 核对置顶评论与咨询入口，未授权的评论只留预览。
   - 预约时核对具体日期、时间和时区及页面回显。
   - 保存提交预览截图，列出账号、版本和最终内容。
   - 停在最终发布/预约按钮前，交用户确认这份预览。
3. 收到最终确认后，提交一次并回查。
   - 同一份提交预览已有明确确认，沿用该确认，不重复索取。
   - 只执行确认范围内的发布或预约。
   - 评论、置顶和回复仅按该动作的明确授权执行。
   - 从真实平台回查账号、笔记、版本和实际状态。
   - 保存平台确认截图及其实际本地路径。
   - 平台确认后填写 receipt.md，套用下方模板。
   - 审核中只记审核中，预约成功只记已确认预约。
   - 提交超时先查原账号，不自动再次点击提交。

## ④ 输出模板

```markdown
# 发布回执
- 对应版本 <note-id 与成品位置>
- 账号 <账号名与可区分标识>
- 平台 <实际站点>
- 笔记链接 <平台实际返回的链接>
- 提交时间 <具体日期时间及其时区>
- 平台截图路径 <本目录内可打开的原件>
- 平台实际状态 <已发布 / 已确认预约 / 审核中 / 未知>
- 授权来源 <用户对当前预览的确认>
- 预约时间 <仅预约填写，含时区>
```

模拟或隔离单据的首行必须写以下原句。
```text
TEST/模拟。仅验证入口，不代表真实发布。
```

## ⑤ 停点与红线

- 最终按钮前必须取得用户对当前预览的确认。
- 只停在真实回执，或确切阻塞加唯一下一动作。
- 缺账号、素材公开范围或最终确认时，立即停下。
- 缺 receipt.md、缺截图或只有 TEST 回执，不得写「已发布」。
- 逐页记录全部通过且同版本真实回执齐全，才满足已发布条件。
- 平台审核中、预约、提交中和状态未知，均不能写成已发布。
- 不修改已定稿文案，不重做图，不重新找参考。
- 不扩展账号、对象、公开范围或对外消息授权。
- 不绕过平台限制，不另建发布器或定时任务。
