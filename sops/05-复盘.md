# 05 · 复盘

## ① 本步只读

- `workspaces/<业务>/INDEX.md`，定位版本、瓶颈和观察窗口。
- `workspaces/<业务>/PROFILE.md`，核对客户、购买理由和承接目标。
- 本文件 `sops/05-复盘.md`。
- 规则文件到此为止，禁止乱翻 `docs/`、`knowledge/`。
- 只按步骤读取该版本真实回执、后台数据和客户反馈原件。
- 历史分析仅复用相关记录，不批量加载任务。

## ② 本步只写

- 只写 `workspaces/<业务>/analytics/`。
- 本次记录写入 `analytics/<观察窗口>-<note-id>.md`。
- 后台截图和用户导出放同目录下的本次证据子目录。
- INDEX、PROFILE、production 和 publish 保持只读。
- 原始数据保留来源，不覆盖旧记录。

## ③ 执行步骤

1. 锁定同一个版本和观察窗口。
   - 抄下笔记链接、账号、发布时间及实际发布状态。
   - 核对起止日期、时区和后台筛选条件。
   - 尚未发布时，只能复盘制作投入和现有证据缺口。
   ```powershell
   $analytics = "workspaces/<业务>/analytics"
   New-Item -ItemType Directory -Force -Path $analytics | Out-Null
   ```
2. 读取真实数据，逐项填写固定表格。
   - 先读用户给的真实记录，缺项时读取已授权后台。
   ```powershell
   ego-browser skill
   ```
   - 按工具指南复用现有环境，先核对当前登录账号。
   - 保存实际页面、窗口、筛选及截图或导出路径。
   - 填曝光、点击、评论、咨询、试跑、成交和成本。
   - 每项填写数值、单位和能回查的来源。
   - 平台没提供、无权限或没记录，一律写「未知」。
   - 只有真实观察为零时才写 0。
   - 公开互动不能换算为咨询、试跑或付款。
   - 金额缺供应商真实记录时写未知，不用请求数换算。
3. 判断哪一环有反馈、哪一环卡住。
   - 对照同一窗口的数据和真实客户原话。
   - 写清已证实的现象，推断单独标明。
   - 只选一处最有证据的卡点。
   - 只给一个具体改进动作，并说明对应证据。
   - 没有业务数据时，只给一个补齐关键数据的动作。
   - 写完下方模板后停下，不自动执行改进。

## ④ 输出模板

```markdown
# 复盘 · <note-id>
- 账号与笔记 <实际账号及链接>
- 观察窗口 <起止日期、时区、筛选>

| 指标 | 实际数值与单位 | 原件与范围 |
| --- | --- | --- |
| 曝光 | <数值或未知> | <来源及窗口> |
| 点击 | <数值或未知> | <来源及窗口> |
| 评论 | <数值或未知> | <来源及窗口> |
| 咨询 | <数值或未知> | <来源及窗口> |
| 试跑 | <数值或未知> | <来源及窗口> |
| 成交 | <数值或未知> | <来源及窗口> |
| 成本 | <实际金额、人工投入或未知> | <回执及范围> |

- 有反馈的环节 <现象及证据，缺数据写未知>
- 卡住的环节 <现象及证据，缺数据写未知>
- 唯一改进点 <一个动作，附支持它的原件>
```

## ⑤ 停点与红线

- 只输出一处有证据的改进点，交用户决定是否执行。
- 没有数据就停在未知和一个取数动作。
- 不重写稿，不生图，不发布，不扩展渠道。
- 不把测试回执、未发布内容或免费预检写成已验证获客。
- 不混用不同账号、版本、时间窗口或统计口径。
- 不用点赞、评论、收藏或试跑人数推算成交。
- 不把一次变化写成已证明因果。
- 不为了填满表格而编造数据。
