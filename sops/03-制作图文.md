# 03 · 制作图文

## ① 本步只读

- `workspaces/<业务>/INDEX.md` 顶部当前版本。
- `workspaces/<业务>/PROFILE.md` 的购买理由和产品事实。
- 本文件 `sops/03-制作图文.md`，禁止乱翻 `docs/`、`knowledge/`。
- 按步骤读取指定原帖、用户选定母版、真实截图和工具回执。
- 交接只参照 [handoff 模板](../templates/handoff.md)，不另找方法卡。

## ② 本步只写

- 只写 `workspaces/<业务>/production/<note-id>/`。
- 保留 handoff.md、job.json、正文.md、页序.md 和 visual-review.md。
- 材料回执放 materials/，预检放 preflight/，提交放 run/，原图和 ZIP 放 results/。
- INDEX、PROFILE、参考库和原始截图保持只读。

## ③ 执行步骤

1. 复核指定原帖，确认用户已选定母版，再写交接和 Job 结构。
   - 只有小红书链接且未存原图时，先运行 `python -X utf8 scripts/fetch_xhs.py "<链接>" --output "workspaces/<业务>/references/evidence/<ref-id>"`。
   - 下列创建命令仅用于新 note-id，已有交接直接复用。
   ```powershell
   $dir = "workspaces/<业务>/production/<note-id>"
   $reference = "workspaces/<业务>/references/evidence/<ref-id>/<原图文件>"
   New-Item -ItemType Directory -Force -Path $dir | Out-Null
   Copy-Item -LiteralPath templates/handoff.md -Destination "$dir/handoff.md"
   ```
   - 把命令里的占位值替换为本次真实输入。
   - handoff 填业务、note_id、主需求、笔记标题和逐页内容。
   - 每页用 `## 页 N · 角色`，写 page_number、role、generate、exact_text、reference。
   - exact_text 放入纯文本围栏。生成页 generate=yes，截图页 generate=no。
   - 生成页从 1 连续编号，截图页编号放其后，最终混排写入页序.md。
   - 用户已有定稿就逐字沿用。新文案模仿参考原图的行数、字数和说话口气（吐槽/悬念/清单），封面严禁写行业黑话，用目标客户一眼秒懂的大白话 + 有事实依据的具体结果数字抓点击。
   - 写定稿正文.md 与页序.md。截图页使用真实原图和已定图注。
   - 按 handoff 转写 job.json，只转换结构，不改写定稿文案。
   - Job 填 task_id、theme、title、content_mode=final、mode=inspired、reference_policy=layout。
   - page_count 只计生成页，真实截图页不得进入 pages。
   - 每页 title+copy 逐字对应 exact_text，generation.size 沿用确认尺寸。
   - authorization 初始为 approved=false、max_image_requests=0。
2. 真实上传母版，回填素材 ID，再校验和免费预检。
   ```powershell
   python -X utf8 scripts/image_engine.py --config private/image-engine.json --output "$dir/materials" upload "$reference"
   ```
   - 从 materials/assets.json 取真实 asset_id，回填 handoff 和 Job。
   - references 填 asset_id、source、真实 rights、purpose=reference。
   - 每个生成页 asset_ids 对应一张用户确认母版，多张母版在 upload 后追加真实路径。
   ```powershell
   python -X utf8 scripts/handoff_check.py --handoff "$dir/handoff.md" --job "$dir/job.json" --assets "$dir/materials/assets.json"
   ```
   - 校验退出 0 才能继续，失败就停在具体差异。默认 `$job = "$dir/job.json"`。
   - 若用户已批准 1 次视觉分析（调用引擎 `hy4flash` 看原图结构与配色），先执行 analyze 生成 `analyzed-job.json`（只补画面方向，不改定稿文案），后续 `prepare` 与 `submit` 均使用 `analyzed-job.json`：
   ```powershell
   python -X utf8 scripts/image_engine.py --config private/image-engine.json --output "$dir/analysis" analyze --job "$dir/job.json" --analysis-id "<stable-analysis-id>" --approve-analysis-requests 1
   $job = "$dir/analysis/analyzed-job.json"
   ```
   ```powershell
   python -X utf8 scripts/image_engine.py --config private/image-engine.json --output "$dir/preflight" prepare --job "$job"
   ```
   - 校验必须退出 0。prepare 必须 paid_calls=0，保留全部返回。
   - 交预检结果和请求次数，立即停下，等用户明确批准本任务额度。
3. 额度获批后，才执行 submit / query / download。
   - 额度只填用户批准次数，金额未知就写未知。submit 的 --job 已分析用 `"$dir/analysis/analyzed-job.json"`，否则用 `"$dir/job.json"`，沿用上面的 `$job`。
   ```powershell
   $imageRequests = <用户批准的图片请求次数>
   $taskId = (Get-Content -LiteralPath "$dir/job.json" -Raw -Encoding UTF8 | ConvertFrom-Json).task_id
   python -X utf8 scripts/image_engine.py --config private/image-engine.json --output "$dir/run" submit --job "$job" --approve-image-requests $imageRequests
   python -X utf8 scripts/image_engine.py --config private/image-engine.json --output "$dir/run" query $taskId --wait-seconds 30
   ```
   - 未结束时继续查同一 taskId。提交超时不自动重发。
   - 确认任务完成后下载，每页 PNG 和 results.zip 都保留。
   ```powershell
   python -X utf8 scripts/image_engine.py --config private/image-engine.json --output "$dir/results" download $taskId
   Get-ChildItem -LiteralPath "$dir/results" -Filter *.png | Get-FileHash -Algorithm SHA256
   ```
   - 首次交付使用引擎原图。下载有缺页时如实标注。
   - 下载 PNG 后立即停下，展示原图路径，交用户逐张目视验收。
   - visual-review 每页填页码、文件名、SHA256、实际所见、问题、能上/要重做/待看。
   - 验收前填「未取得人工验收 / 待核 / 待看」，保留图片和哈希。
   - 收到逐页人工结论后原样登记，附查看者、日期和对应图片。

## ④ 输出模板

```markdown
- 版本与标题 <note-id> / <定稿标题>
- 正文与页序 <正文.md> / <页序.md>
- 原图与完整 ZIP <实际路径，缺失项写明>
- Job 与回执 <job.json> / <run> / <results/downloads.json>
- 图片请求次数 <实际次数>，供应商金额 <实际金额或未知>
- 逐页检查 <visual-review.md>，当前结论 <待目视检查>
- 唯一下一动作 <请逐张看图并给出能上或要重做>
```

## ⑤ 停点与红线

- 母版未由用户确认，停在选图。额度未批准，停在免费预检。
- PNG 下载后强制停在人工目视验收，不自行升级为可审核。
- 人工验收前，正文、页序和交付清单统一标「待目视检查」。
- 单据缺页、空字段、哈希不符或有待看/要重做时，仍为待目视。
- OCR、尺寸、哈希和文件存在均不能证明「已看过」。
- 禁止模型改写定稿，禁止 PIL/HTML 代画整套图，禁止画假软件界面。
- 不复制原作者品牌、水印和原创插画，不伪造素材 ID、批次或案例。
- 不擅自增加分析、重试或修订费用，不发布，不跨入下一板块。
