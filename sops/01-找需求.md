# 01 · 找需求

## ① 本步只读

- `workspaces/<业务>/INDEX.md`，只读顶部当前版本与缺口。
- `workspaces/<业务>/PROFILE.md`，读产品事实、主需求和购买理由。
- 本文件 `sops/01-找需求.md`。
- 规则文件到此为止，禁止乱翻 `docs/`、`knowledge/`。
- 用户提供的材料和本步取得的原帖，只作为证据输入。
- 历史任务不批量读取，已有有效证据直接引用。

## ② 本步只写

- 只写 `workspaces/<业务>/research/`。
- 研究结论写入 `research/<任务名>.md`。
- 原帖截图、摘录和工具返回放在同一研究目录。
- INDEX 和 PROFILE 保持只读。
- 沿用原证据路径，不覆盖原件。

## ③ 执行步骤

1. 锁定本次要查的客户任务。
   - 从 PROFILE 抄下已确认的主需求和购买理由。
   - 写明客户在什么现场、要交什么结果。
   - 先列本次真正缺少的证据。
   - 只建立本步输出目录。
   ```powershell
   $research = "workspaces/<业务>/research"
   New-Item -ItemType Directory -Force -Path $research | Out-Null
   ```
2. 核对客户原话与现有替代办法。
   - 先用已有原件，缺证据时用现有 ego 只读调查。
   ```powershell
   ego-browser skill
   ```
   - 按工具指南复用已有环境，遵守业务指定站点。
   - 打开原帖和相关评论，保存链接、时间及必要截图。
   - 摘录原话，保留上下文，不补写没读到的评论。
   - 区分真实求助、同行宣传和自己的推断。
   - 查清客户现在用什么办法、付出什么代价。
3. 把证据填入下方模板。
   - 只整理客户任务、购买理由、替代办法、原话和未知项。
   - 一条结论对应一个原链接或本地原件。
   - 只有求助时，只能证明存在求助。
   - 主需求变化写成待用户判断的冲突，不更新档案。

## ④ 输出模板

```markdown
# 需求证据 · <任务名>
- 客户任务 <谁在什么现场，要交什么结果>
- 购买理由 <为什么愿意买，缺证据则写未知>
- 产品差异 <档案已确认的选择理由>
- 现有替代 <工具或人工办法及实际代价>

| 原话 | 原链接或原件 | 观察时间 | 能证明什么 |
| --- | --- | --- | --- |
| <逐字摘录> | <来源> | <含时区> | <有限结论> |

- 未知项 <尚缺哪项事实>
- 档案冲突 <无，或列出新证据与影响>
- 唯一下一动作 <一个具体动作>
```

## ⑤ 停点与红线

- 证据足以回答本次问题，立即交证据并停下。
- 改变已确认购买理由前，交证据与影响，等用户拍板。
- 缺产品对象、登录或原件时，只提一个补充动作。
- 不写标题、正文或逐页文案。
- 不建立参考库，不生图，不发布。
- 不把高赞、搜索联想或自述身份当成交证明。
- 不虚构购买者、价格、效果或需求规模。
- 不绕过验证码，不导出账号凭据。
