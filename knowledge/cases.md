# 从案例提炼方法，保留边界

案例用于改善判断，不用于借别人的成功证明自己的打法。下面是原作者资料的有限归纳，没有把供应商宣称当作独立效果研究。

## 案例一：分组异常实际上是 ID 错误

**原始事实**：[Microsoft ExP 的案例说明 S26](sources.md#s26) 记录了一次设备 ID 问题：部分用户此前拿到重复 ID，修正后，一组仍读取旧值、另一组使用新值，导致样本比例异常；团队定位后修正并重启实验。

**可迁移的方法**：看到结果异常，先检查计数对象、数据来源和执行是否一致，再解释用户偏好。营销中的重复线索、渠道去重不一致、不同退款窗口也可能影响解释，具体是否发生仍需查看本业务原件。

**不能迁移的部分**：该案例没有证明当前业务需要告警平台，也没有提供一套通用的营销转化阈值。GoFind 只要求按问题核对必要数据，不复制其基础设施。

## 案例二：信任来自可理解和可核对的信息

**原始事实**：[NN/G 的网站研究 S11](sources.md#s11) 描述研究参与者如何借助信息组织、披露和内容准确性评价网站的可信度。其例子来自具体历史网站和研究场景。

**可迁移的方法**：有访问没咨询时，检查用户是否能理解产品适合谁、费用和条件在哪里、案例能否核实、内容是否及时，再决定怎样修改。可以通过用户能否解释清楚报价、是否找到下一步来测试理解。

**不能迁移的部分**：不能宣称某种配色、白底、按钮或披露方式会给所有平台带来固定比例的成交提升；也不能用感知可信度替代履约和产品真实效果。

## 案例三：看似需求，其实来源身份不明

**实际执行**：[GoFind 公开调查](../examples/gofind-channel-research/README.md) 读取了相关仓库的 README 和 issue。一个涉及中国中小商户的帖子自称 Agent 代表团队，另一些建议来自项目维护者；它们不构成独立目标客户样本。

**可迁移的方法**：提取用户需求前，核对发布者与产品关系、发言上下文和是否真的发生行为。把此类资料保留为话题/竞争线索，而非直接删除，也不升级为付费需求证据。

**下一步**：用可复现的调查实例向自愿参与的真实用户验证使用价值。当前调查没有公开发布、没有招募，也没有观测到获客/销售结果。
