# 从真实问题制作内容

**适用**：选题、标题/封面、图文、短视频脚本、产品介绍与内容改稿。简单改稿直接交成品；选题依赖现状时再调查。

用户提供了足够的原稿与产品条件时，直接修改。需要选题依据时才打开真实问题、原内容和评论，使用调查结果选择表达。

**研究基础**：[S02](../sources.md#s02) 的客户任务，[S11](../sources.md#s11) 的信任研究，[S06](../sources.md#s06) 对独特、实用、面向人的内容的建议。下面是 GoFind 的制作方法；格式不是平台流量公式。

## 先确定内容完成什么事

从真实提问、售前顾虑、反复失败的步骤、比较条件或产品可验证的使用过程找选题。不要从一个无关热点硬凑产品。只有候选没有调查时标为探索选题。

用户没有给选题、专业内容没人看或需要持续经营时，按 [内容判断与账号认知](content-strategy.md) 追查问题、解释和切口，再制作。已有原稿的单次修改不走完整调查；发现关键主张无依据时修正该主张即可。

明确读者情境、要解决的问题、可展示的证明和看完后的一步。证据可以是实际演示、清楚的规格/条件、有授权的案例和可复现步骤；没有的结果不写，不用虚构证言、订单截图或收益承诺补强。

## 不同内容怎样制作

形式按当前问题、已有证据和投入选择：能用正文与现有合适图片讲清，就先做图文；需要看连续操作再用短录屏；完整宣传片只有在明确销售/复用用途值得时安排。没有新视频不阻塞已能准确表达的内容，也不能把旧图片伪装成新实测。下表是可选用途，不是固定内容分类或所有产品笔记的必备项。

| 场景 | 成品应包含什么 | 选择理由 |
| --- | --- | --- |
| 搜索图文/问答 | 直接回答问题、具体条件、步骤/对比、限制、可用下一步 | 用户正在主动解决问题，兑现比悬念更关键 |
| 推荐图文/短视频 | 让目标人认出情境与阅读理由，用经历、观点、故事或演示兑现相应承诺 | 注意力有限，内容应与最初产生的兴趣相连 |
| 软件/数字产品演示 | 实际输入到输出、关键操作、适用环境、数据/价格限制、试用如何获得价值 | 抽象功能表难以证明能完成任务，不强迫其他软件相关内容都做演示 |
| 本地服务/商品 | 真实规格/环境/过程、价格包含项、适用范围、时段/预约和履约条件 | 用户同时在判断匹配、信任和能否实际使用 |
| 信任/比较内容 | 同条件证据、替代办法、谁适合/不适合、公开限制 | 降低选择成本，避免泛泛吹优势 |

图文要给出完整正文与必要配图说明；视频要给口播、画面/演示和字幕重点。长度由问题、平台限制和素材决定，不强制“黄金三秒”“某个时长必爆”。没有真实画面时把拍摄需求写清，不把想象的镜头标成现成素材。

## 参考图文与创作交接

先区分当前在找什么：找客户看真实任务、困难与购买条件；找选题看受众关心的问题和已有答案；找参考看内容怎样吸引、解释和证明；写获客笔记再把这些依据与产品事实结合。可以组合，不要求每次完整走一遍。业务续接复用已确认资料，只补影响本次决定的缺口。

只说“找几篇值得借鉴的图文”而没有行业时，可以从原生发现页或实际可见内容开始探索，不默认绑定最近一个产品，也不因缺行业停止。根据看到的兴趣来源、阅读收获和评论反应，决定下一次打开什么或怎样查询；结果反复是同一套路，就换要比较的表达问题或发现入口，不只换相近行业词。参考可以来自任何领域，不设行业、关键词或图文类型白名单，也不为跨行业本身凑案例。用现有浏览器查看原图，操作沿用 [浏览器指南](../../docs/browser.md)，不另造抓取器。

- **两条依据分别找**：工作困难、选型/试用/价格提问及实付分别登记；参考的表达和可见互动另记。好看的封面、高收藏或跨行业咨询不能证明本业务愿付费，也不能确定流量来源。
- **进入核心参考前实看**：记原链接、作者、原文日期与观察时间、可见互动/评论；实际查看封面和必要正文图片，记总页数、已看页码、每页信息作用和未读范围。轮播切页后等图片与动画稳定再截图，并用视觉能力打开截图理解；保存文件不等于已看懂。只看到缩略图就保持候选，不称完整拆解；读不到的页保留限制。
- **分开理解吸引、收获与商业联系**：从具体情境、题目、图像和正文判断谁可能立刻形成疑问、代入经历、作出判断或想看后续；这些是解释假设。点开后可能得到答案、经验、观点碰撞、共鸣、故事或操作方法，不统一要求完整教程。实读评论核对人们在争论、补充还是追问；点赞、收藏、评论总量分别保留，不直接代表喜欢、学会、点击率或成交。同一参考可以值得学讨论方式，却不足以证明产品价值。
- **选择和淘汰要对准用途**：说明原帖对哪类读者的什么利益/经历有吸引力，图片怎样帮助识别和阅读，正文兑现了哪种承诺，评论支持什么及还有什么替代解释。讨论没有标准答案不等于空承诺，低赞不等于无用，争议多不等于值得复制。可只保留某种方法，不整篇推荐；夸大承诺、无可迁移价值、需编造效果或换标题重复的候选应放弃，并说明针对的用途。
- **迁移方法，不换名词**：先提炼作用于什么人、为什么可能有效及成立条件，再用本业务真实问题重建情境、观点/故事/解法和画面。原帖读者不属于本业务买家不妨碍借鉴，但新内容必须能解释与自己客户的联系。若只把产品名换进原题就失去切身利益，或正文只能突然插广告，该迁移不成立；可以放弃，不必硬凑。生产条件用于选择怎么实现，不以易制作或漂亮代替运营价值。
- **制作前回答商业问题**：给谁看、为何在意、正文交付什么、依据是什么、看完怎样自然继续。可以是知识、问答、经验、演示或选型，不强制每篇推销软件。各套按实际问题区分，不固定页数、结构、报价或“扣1”；数量受限则说明实际完成与缺口，不灌水。
- **同时检查发现与阅读**：自然写出用户可能搜索的实际问题和答案，并让不带搜索上下文的读者从封面看懂价值；解释偏搜索、偏推荐或兼顾的取舍。没有原生联想或后台数据时将候选表达与真实出现的词分开，不把加关键词/话题当效果验证。

交给独立生图工具前核查当前接口：是否支持链接导入、视觉分析、页面规划与准确文案生成，各自需要什么输入、会不会产生费用。工具已有的参考解析与图片生产不重复开发；可交原始链接、要借鉴的方法、原创主题、受众/目标、准确标题正文、真实产品事实与边界、可用素材及缺口，不先强制写多页设计报告。具体视觉解析可交工具，原创判断和事实不能让它代造；需要付费分析时另有实际授权，本轮未授权就只准备交接资料。

按实际 `Job/Page` 契约选择交接深度：`brief` 可交明确内容与规划要求，复查工具返回的页面是否忠于原文；`final` 或用户明确要逐页审核时，写全每页准确标题/正文、角色、画面与素材要求，不能只写“这一页介绍痛点”。免费本地规划只组织已给事实，不自动等于完成创意或视觉分析。实际界面只用真实获权截图，旧图标版本与范围，缺图用明确标“示意”的抽象图，不生成假UI或结果。现有任务记录加必要 JSON 即可，研究与发布元数据放严格请求之外。

链接可导入不等于已导入；严格请求的 `source` URL 不自动触发抓取。按实际返回核对素材与ID映射，未取得真实 `asset_id` 时保留原链接/本地路径和待绑定用途，不伪造。没有附件、只迁移通用方法时可用 `original`；需实际参考图的 `inspired` 在导入及权利核对后再选。授权、分析、图片和发布分别记录；费用未授权保持未授权，不能把 `final` 或本机令牌当许可。缺新截图不阻塞能准确完成的文字。

交付前按本次范围回查：来源与已看范围、需求依据、事实、封面兑现、完整文案、必要素材和接口可交接性；批量再查差异。字段校验只证明格式；真实浏览器观察、内容自检、独立行为和咨询/付款分别报告。下一批复用有效资料，按新问题补查。

## 标题、封面与行动入口

标题和封面共同说明对象、问题或可证明结果；正文兑现同一个承诺，包括观点或经历，不要求都给教程。视觉重点要帮助读者认出情境和理解内容，不能只模仿字体配色，也不能忽略图片。备选标题对应不同的兴趣理由与读者阶段，不是随意换同义词；具体取舍见[传播切口](content-strategy.md#传播切口怎样选)。

动笔时先给客户能识别的具体问题，再给答案/演示和依据；需要专业条件时保留条件，用例子解释，不用术语堆积代替推理。成稿后反查：开头问的事是否回答、对比是否同条件、是否把可能原因写成唯一原因、切口扩大后是否仍服务目标客户。不能只把标题写得更刺激而正文不变。

行动入口与用户阶段匹配：继续自助、看演示、检查适配、询价或预约。不要每条都要求关注/私信；平台规则、账号资格和入口可用性要核实。发到不同平台时重做标题、节奏、证据和路径，不只替换话题标签。

## 改稿和验证

先定位当前问题：对象模糊、只列功能、证明缺失、承诺与内容不符、入口不可达，还是信息不必要地拖长。直接给修改后的成品，并用一两句说明关键改变。产品条件未知时保留明确待核项，不能称“可直接发布”并夹带未经核实的报价。

效果按内容目的衡量：是否被相关用户看见/读到、是否理解、是否产生合格行动及后续成交/使用。标题点击高但无合格行动，检查承诺错配；完播低先看内容长度、用户匹配与留存位置，不能自动归因开头。测试时记录版本与混杂因素；高互动只是观察，不自动升级为可复制经验。

用于长期系列时，保留这条独立回答了什么、共同证明哪个客户认知、承接哪份相关内容；这些内容可以不带销售入口。单条获客稿则按具体购买任务写合适下一步，不为套系列而拆散答案。

原稿的问题一旦能由现有条件确认，就交付修改稿。剩余不确定只影响表现预期时，用不同表达检验同一具体问题。若连产品效果都未核实，使用可核对的功能或实际步骤完成草稿，列出发布前必须核实的承诺。
