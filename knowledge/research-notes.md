# 研究如何转成项目能力

2026-11-09 的开发研究优先读取公开原始机构、方法提出者、平台文档与实践团队资料，再观察相关开源实现。完整来源与访问范围见 [来源登记](sources.md)。私人 Skill 只曾作为补充阅读，未复制其正文、私有模板或绝对路径；核心方法由公开资料和当前需求独立组织。

## 保留的依据与交叉核查

| 要解决的判断 | 核查的不同资料 | 转成的实际动作 | 仍然不能断言 |
| --- | --- | --- | --- |
| 谁需要并愿意付出 | SBA 的市场/替代价格视角 + Strategyzer 的客户任务视角 | 查真实事件、替代行为、购买条件，区分访谈和实际使用/付款 | 画布或几条评论已经证明市场规模 |
| 有流量是否有效 | Search Console/GA4 的明确计数口径 + Microsoft 的数据质量/实验实践 | 查分母、去重、成熟期和混杂，区分归因与增量 | 高互动或最后点击证明净获客贡献 |
| 内容是否值得信 | NN/G 的原研究 + Google 的内容指导 | 给清楚条件、一手证明和可用答案，检查用户理解 | 某种写法或配色必然高转化 |
| 定价怎样站得住 | Stripe 的定价视角 + SBA 的竞争/价格研究 + 客户价值方法 | 同口径比较报价，核对交付成本，测试实际接受与后续结果 | 通用定价公式或意向提问决定正确价格 |
| 平台能不能照搬 | Google、GitHub、Reddit、美团各自官方说明 | 规则限定平台/业务/日期，未知平台现场核查 | 一个来源覆盖全部平台 |
| 如何复用现成 Agent | Codex 官方入口 + 已有公开营销/分析项目 | 根目录规则、按需阅读、宿主工具执行；文件保存经验 | 加载指令就保证 Agent 永不犯错 |

这里的“交叉核查”主要核查概念边界与兼容性，不把不同资料说成共同测出了 GoFind 的业务效果。S05 与 S06 来自同一机构，不计为两个独立实验；工具 README 和它自己的案例也不是独立验证。

## 排除和降级的说法

- 未采用“20 年专家”“顶级大师”等角色赋能方式；方法必须能指导取得证据和完成工作。
- 未采纳“固定完播率必推流”“固定时间必爆”“结果少就是蓝海”等算法传闻；未取得官方正文的来源登记为线索。
- GEO 没有被做成流量承诺；官方 Google 资料只支持其产品范围内的说明，其他引擎需要真实测试。
- 已有开源项目证明相关供给存在，不能证明本项目已经有差异或中文市场需求成立；示例调查保留了不支持乐观判断的资料。
- 没有引入数据库、固定运营编排、平台 SDK、CSV 产品或重新封装 Agent；当前任务通过标准文件和宿主工具完成。

## 平台资料的缺口怎样处理

小红书学习/聚光、抖音透明度/电商罗盘的部分官方页在本工具下不可读；视频号当前分发和账号商业功能也未取得可核查正文。因此相应卡提供调查方法，明确把当前机制、功能和权限留给真实任务核查。其他平台不为了覆盖数量制造“专业规则”，使用新平台调查卡按证据适配。

## 更新一条知识需要什么

先指出当前任务中缺少什么方法或哪条说法已失效，再读能回答它的原始资料，核对日期、对象和定义。把改变落实到实际工具动作、判断/验证或成品上。只增加能改善任务的内容，删掉过期重复说法；保存旧结论变化原因。不能只加一批文章链接，也不能把一次测试结果写成通用规律。
