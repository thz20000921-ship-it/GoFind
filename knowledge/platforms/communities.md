# 开发者社区、GitHub 与软件/数字产品

**使用场景**：目标用户会寻找工具、比较替代方案、讨论实际故障，且产品能提供可演示的价值。社区不是可自由群发的客户名单。

**已核查规则**：[S14](../sources.md#s14) GitHub 限制垃圾推广、滥用个人信息和在他人账号中过度商业内容；[S15](../sources.md#s15) Reddit 禁止重复或未经请求的大规模互动，社区还有自己的规则。具体讨论区/论坛要再看本地规则。

## 从实际任务找人群与入口

读取相关仓库 README、文档、公开 issue/discussion、论坛任务讨论或产品比较。记录原样查询、选样、时间、状态和发布者与项目的关系。issue 可能是维护者计划、自动生成建议、机器人宣传或技术缺陷；不自动代表独立买家，更不以 issue/星标数量估算客户规模。

调查用户如何开始和完成关键任务：安装/接入、输入到结果、适用环境、数据权限、价格、替代成本。公开演示能证明的和 README 自述的分开。竞品支持多工具，只能先证明其公开声明，未实际使用就不宣称功能已测。

识别可以贡献真实价值的位置：回答明确技术/使用问题、自己的可复现教程、允许展示的项目区、实际比较和公开案例。遵守对方规则，不在竞品问题下夹广告，不为曝光制造 issue 或伪装普通用户。

## 把价值做出来

软件内容优先展示真实任务、最短可用入口、必要环境、示例输入输出、数据边界和谁不适用。给用户可复现结果，而不是抽象“AI 提效”。下载/注册后第一次成功完成任务往往比点击更能说明价值，但仍要看是否是目标客群。

制作教程、README 修改、演示脚本、论坛答复草稿或比较页。产品尚未公开时不能编造下载链接、用户评价或安装成功案例。发布和对外回复需要具体授权；可先准备最终内容和适合的真实位置。

## 怎样验证

区分关注/收藏、仓库访问、下载/安装、完成关键任务、持续使用、付费。取不到下载后行为就写未知，不把 star/fork 当激活。通过用户自愿、知情的反馈了解障碍，不暗中收集个人信息。

公开示例 [GoFind 调查](../../examples/gofind-channel-research/README.md) 已实际展示了仓库与 issue 核查、信号降级、差异选择和内容制作；它没有证明有付费需求。
