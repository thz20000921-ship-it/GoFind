# 抖音获客与经营诊断

## 何时使用

用户要求通过抖音获客、研究搜索/推荐/直播内容，或解释咨询、商品和团购成交变化时，主动使用本卡。只改一段已提供的口播时直接制作。先确定希望改善的是合格咨询、试用、付款、核销还是净贡献。

[S17](../sources.md#s17) 与 [S18](../sources.md#s18) 在 2026-11-09 未取得可读正文。以下为 GoFind 的工作方法，实际指标定义、商业入口和权限在当前账号核实。

## 按获客路径选择调查

- **搜索**。观察原生联想、实际结果、用户问题和对比条件。根据评论中的任务表达扩展候选，比较答案是否满足意图。
- **推荐短视频**。看相关用户怎样识别场景、何时看懂产品价值、演示是否可信和能否行动。有自有留存数据时定位实际离开位置。
- **直播**。记录相关讲解片段、商品/服务条件、用户提问和主播回应，再核对点击、付款和退款。主播口头报单仅作为其表述。
- **商品或团购**。检查内容展示到商品页、报价条件、咨询/下单的完整路径。诊断时读取相应交易与履约记录。
- **本地服务**。把地区、服务半径、可约时段、套餐和核销条件放入匹配判断，结合 [本地生活卡](local.md) 检查接待能力。

抖音网页多依赖 JavaScript 渲染，纯 HTTP 通常只返回空壳。需要界面或登录态时，直接使用已可用的 ego 与 [浏览器指南](../../docs/browser.md)。观察来源不明时不能由视频形式推定实际流量来源。

## 已有业务先找变化发生在哪一段

用户要求解释“最近七天”时，先确认业务账号与所在时区，读取有明确日期起止的目标期间和可比期间，记录两段是否等长、是否都覆盖完整日期，以及活动、节假日和观察成熟度的差别。已有授权范围内的只读后台可直接打开，账号不明确才询问。

优先取得本次问题需要的原始字段。曝光/进入、商品点击、咨询、支付人数/订单、退款/取消、核销/履约、结算与成本分别核对定义、去重和日期归属。退款率、核销率可能需要同批订单成熟窗口，不能用不同日期归属强拼漏斗。字段缺失写未知。

先比较绝对变化，再定位值得深查的一段。

- 支付下降而点击相近时，回查商品/套餐、价格条件、库存或可约能力、支付入口与实际异议。
- 点击下降时，查来源与人群、内容到商品的入口、商品是否下架或不可见，再看相应内容表现。
- 支付相近但退款增加或核销变差时，优先查履约、可用时间、描述错配和售后，按订单批次核对。
- 各来源占比变化时分开比较，避免把客群组合变化解释成同一内容效果下降。
- 表现与后台变更时间吻合时，把变更视为待验证原因，回查原件和其他变化；先修复可复现的入口故障。

这里的条件用于选择下一次读取。没有对应字段时先查可取得的相邻环节，不能凭播放量判定成交原因，也不等完整报表才处理已确认问题。

## 没有后台时怎样继续

读取公开内容、商品页、可见评论和路径，保存实际查询、片段时间、报价与用户具体问题。选择相近账号的普通、较低互动和高互动内容比较，分清同行交流、使用者提问和商家自述。

公开材料可以帮助检验展示、适配和入口，无法直接解释本账号净成交变化。已有截图/导出可继续核对口径，需要关键私有字段时一次说明缺什么和它影响哪个决定。能完成的脚本、页面文案或演示方案先完成。

## 从观察进入制作

让目标用户快速认出情境，展示真实输入到结果、使用过程和必要限制。消费品说明规格与使用条件，软件说明环境与关键步骤，本地服务说明范围、预约和履约。根据实际障碍，直接交付修订稿、镜头顺序、商品条件说明或咨询答复。

当前动作应对应观察，例如“评论集中问能否处理某类素材，现有演示没展示它，先补一段真实处理过程”。把动作、完成状态和验证指标写在同一任务中。发布、改价和投放依具体授权执行，已获同范围授权继续推进。

## 何时停查与复查

根因可复现，或证据足以选择能区分关键解释的小测试时，进入修复/制作。重复刷相同题材、不会改变当前动作时结束该分支。账号或字段受限时保留缺口并交付可完成部分。

按相同目标与口径观察合格行为，再看付款、退款、核销和贡献。记录版本、价格、时段、人群及投放变化，复查时间覆盖购买与售后成熟期。自然分发的不同视频提供探索对比，不能由一次表现断言长期因果。配合 [测量](../methods/measurement.md)、[转化诊断](../methods/conversion.md) 和 [实验](../methods/experiments.md) 使用。
