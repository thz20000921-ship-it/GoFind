# 选择现在最值得做的动作

## 五个独立入口

用户点名哪项就做哪项，交付后停在该项。要串联多项时按本次明确要求执行。目录均相对 `workspaces/<业务>/`，每项产物只写指定目录。索引只维护唯一当前版本与续接状态，业务档案只记录已确认的变更。[业务目录](memory.md)

### 找需求

- **输入**　用户给的产品、目标客户或待核问题，外加已有访谈、帖子和业务原件。
- **只写**　`research/`。记客户实际要完成的任务、购买动机、现在的替代办法和对应证据。
- **停点**　交付需求证据与未知项。正文、参考库、生图和发布各有独立入口。

### 找参考

- **输入**　已有客户问题、要改善的表达或用户指定的参考范围和数量。
- **只写**　`references/`。用现有 ego 打开真实小红书原帖。分别判断推荐流为何让人停下、搜索流为何对题且值得点、换成本业务还能靠什么成立。高赞、漂亮封面或跨行业单独不足以入选。[找帖方法](../knowledge/platforms/xiaohongshu.md#图文参考怎样找)
- **停点**　在 `references/REFERENCES.md` 记原链接、吸引原因、可借方法和限制。工具把需要留存的截图放在临时目录时，把截图复制到 `references/`，用库内相对链接引用。交付实得的合格篇数和访问缺口，停在参考。

### 制作

- **输入**　用户指定的参考链接或库内条目，以及档案里已确认的客户任务、购买理由和产品事实。「照这个做」从核对参考开始，沿用已确认的需求和选题方向。
- **只写**　`production/<note-id>/`。复核参考后先写标题、正文和逐页内容，再按授权调用现有图文引擎。首批图片交引擎下载的 PNG 原图。用户只要文案时交文案。[图文制作](#图文制作)
- **交接**　固定两份文件：`handoff.md`（给人看：逐页 exact_text、参考映射、must_keep／must_not）和 `job.json`（给生图项目：`mode: inspired` + `reference_policy: layout`，每页 asset_ids 只能填真实上传 ID）。用 [图文交接模板](../templates/handoff.md) 起稿，用 `python scripts/handoff_check.py` 校验两者逐项对应。
- **分工**　GoFind 负责选题、标题、逐页文字、参考选择和验收；生图项目负责链接导入、上传、layout 生成、下载和回执。
- **停点**　交正文、页序、原图和同目录 `visual-review.md`，保留 Job、回执和引擎下载 ZIP。逐页填写与状态判定按[逐页查看与交接](evidence.md#用工具结果确认实际动作)。缺费用授权或其他工具条件时指出具体缺口。

### 发布承接

- **输入**　用户选中的已审核版本或索引指向的已审核版本，具体账号、平台和外部动作授权。
- **只写**　`publish/`。核对账号、已有图片及页序、正文、评论或咨询入口。按该版本、账号和动作的授权发布、预约或回复。[执行与中断恢复](browser.md#发布预约与中断恢复)
- **停点**　交真实平台回执，或写确切阻塞及唯一下一动作。真实发布在 `publish/` 对应提交目录留 `receipt.md` 和平台截图（[回执要求](evidence.md#用工具结果确认实际动作)），再按[索引条件](memory.md#用索引决定用哪个版本)记状态。隔离、模拟或 fixture 的单据首行写「TEST/模拟。仅验证入口，不代表真实发布。」在用户回复、索引和发布报告中使用下方结果行，随附真实提交的确切阻塞和唯一下一动作。沿用原成品与审核记录。[发布证据](evidence.md#用工具结果确认实际动作) · [索引状态](memory.md#用索引决定用哪个版本)

  > TEST/模拟。仅验证入口逻辑，不代表真实平台发布链跑通。

### 复盘

- **输入**　观察窗口、来源和能取得的真实曝光、点击、评论、咨询、试跑、成交或成本记录。
- **只写**　`analytics/`。按实际口径回答哪一环有反馈、哪一环卡住。缺失数据写未知。[测量](../knowledge/methods/measurement.md) · [实验](../knowledge/methods/experiments.md)
- **停点**　交付有依据的一处改进。制作新内容和扩展渠道留给后续明确要求。

## 用户只说继续时

从最近实际发生的事判断当前瓶颈。选一个主要动作和一个反馈，明确拿到反馈后准备作什么决定。

| 现阶段卡在哪里 | 优先做什么 | 主要反馈 |
| --- | --- | --- |
| 产品或交付不清 | 核对影响承诺的主要入口、支持条件和实际输出 | 现有版本能交付什么 |
| 不知道谁真有需求 | 查具体工作、替代办法和购买条件 | 哪个真实情境值得先试 |
| 有方向、缺可测试成品 | 完成一份可用的内容、报价或演示 | 成品能否解决选定问题 |
| 有成品、尚未触达 | 核对实际可用的渠道与承接，做一次获准的分发或试跑 | 平台确认或客户实际接触 |
| 已触达、人没理解或没问 | 读来源、实际评论和内容，核对承诺与入口 | 目标读者卡在哪一步 |
| 有咨询、没试用或购买 | 查真实适配、报价、试跑和拒绝理由 | 客户是否愿意用自己的材料试，或为什么拒绝 |
| 已购买、交付有卡点 | 修首次成功使用、适配或售后 | 客户能否完成约定任务 |
| 已交付、贡献未知 | 核成本、退款、复购与容量 | 净贡献和承接能力 |

比较能取得反馈、符合当前策略的少量路径。自有搜索内容适合承接正在找答案的人，推荐内容可帮助用户认出问题。合作演示、已有人脉转介绍或获准的小样试跑，有时能更快靠近购买条件。渠道选择取决于对象、承接与成本。明确停用的路径保持停用。

## 何时结束调查或准备

先查一个能改变决定的问题。广告太多就查用户的工作过程、评论和替代办法。新的用户原话可触发场景词，冲突先核原件与反例。调查只持续到有足够证据选一个可逆动作，或明确指出访问受阻及影响。查询条数、互动量和自报读取无法填补关键证据空缺。[证据判断](evidence.md) · [知识导航](../knowledge/INDEX.md)

用户只说继续且已有可测试成品时，先复用它取得下一层反馈。发现明确事实错误、公开权利或重大承诺风险、新证据实质改变人群或交付、成品无法使用时，只修受影响的部分。视觉意见、另一种相近说法或又一个参考，单独不足以启动同题新稿或再审核一轮。

已有检查结果和版本一致时沿用。`prepare` 在输入、页数、素材或接口有实质变化、接近实际提交或定位具体故障时才有价值。相同预检没有新证据价值时，到此为止。出现具体审核问题就查该问题，完成后引用现有证据。

## 缺外部条件时

做到授权内最有价值的一步，再指出当前阻塞。只提出一个此时值得做的外部动作。缺账号就先指定账号。准备齐但缺提交许可时，给确切版本、账号或对象、提交范围和要取得的反馈，提出该次许可后停下来。索引只在状态或阻塞变了时更新。发布、对外联系、收费和付费仍以具体授权为准。

## 图文制作

最终创作者按内容方法选择参考、写原观点并定稿。用图文引擎制作时，可用有公开权利的截图表现真实软件界面，连续操作或产能用真实录屏或过程原件证明。[内容制作](../knowledge/methods/content.md) · [图文引擎](image-engine.md)

**不许做的三件事**：用 PIL、HTML 或本地排版替代整套图（真实截图页原样排版除外）；让模型改写已定稿文案；让模型画软件界面、批次结果或剪映轨道。真实截图页不进 `job.json`，按原始像素排版。

若客户需要相信交付能跑通，优先复用一段从实际输入、生成、修改到验收的演示。必须新跑时，记实际版本、素材条件、失败、人工修正和总投入。示例图与开发者实测可按其范围使用。
