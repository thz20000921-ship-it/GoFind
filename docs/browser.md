# 浏览器交接与取证

## 何时必须用浏览器

- HTTP 只返回空壳、加载提示或极短正文，需要等待 JavaScript 渲染才能读取目标内容。
- 资料或入口依赖已授权账号的登录状态。
- 需要观察原生界面上的搜索联想、排序与筛选、评论区、私信入口或商品入口。

用户要求研究真实平台、竞品或经营表现，就主动发现相应入口并开始只读调查，不等用户提醒调用 ego。已授权只读后台可直接查看；不能访问时先查明原因，再请求必要的登录或原件，不把整项任务交回用户。

## 入口与降级顺序

从第一项开始，选择能在当前权限内取得所需证据的入口。若不可用，按顺序继续，记录实际尝试、结果和证据缺口。

1. **宿主的 `ego-browser` Skill**。从当前会话的 Skill 列表加载并遵循说明。常见宿主的入口如下。

   | 宿主 | 加载与调用 |
   | --- | --- |
   | DSH（DeepSeek Harness） | 在已启用 `@ego-lite/dsh-plugin` 的 profile 中启动 DSH，调用 `/ego-browser`。例如插件装在 `web` profile 时，用 `dsh --profile web` 启动。[ego 插件说明](https://upd.dev/citrolabs/ego-lite/src/branch/main/plugins/ego/README.md#deepseek-harness) |
   | Claude Code | 用户级 `~/.claude/skills/ego-browser/SKILL.md` 或项目级 `.claude/skills/ego-browser/SKILL.md` 中的独立 Skill 可用 `/ego-browser` 调用。通过 ego 插件加载时用 `/ego:ego-browser`。[Claude Code Skill 说明](https://code.claude.com/docs/en/skills) · [ego 插件说明](https://upd.dev/citrolabs/ego-lite/src/branch/main/plugins/ego/README.md#claude-code) |
   | Codex | 从用户级 `~/.agents/skills/ego-browser/SKILL.md`、项目级 `.agents/skills/ego-browser/SKILL.md` 或已启用的 ego 插件发现 Skill。在支持的界面可显式选择 `$ego-browser`，CLI 可用 `/skills` 查找。[Codex Skill 说明](https://learn.chatgpt.com/docs/build-skills) |

2. **直接调用 `ego-browser` 命令**。先运行 `ego-browser skill`，按当前安装版本返回的指南操作。接口和调用参数以该指南为准，GoFind 不保存 ego 的 API 参考或调用实现。
3. **宿主自带浏览器**。使用当前会话可用且有权限的渲染型浏览器，核对它实际能访问的页面、账号和地区。
4. **用户截图或导出**。说明需要的页面、查询与筛选，要求附观察时间。按用户提供的资料登记可见范围和缺失字段。
5. **纯 HTTP**。仅用于发现公开链接、标题或摘要等线索。缺少渲染或登录状态时，明确正文与界面证据未取得。

DSH 中“ego 已安装”“当前 profile 注册了 Skill”“Agent 已读取 Skill”“命令能运行”“原页能读”分别核对。Skill 未出现时，先确认本次实际使用的 profile；需要诊断且命令可用时，用 `dsh --profile <实际名称> --dump-config` 核对 ego 包对应层是否加载，不默认切到示例中的 `web`，也不保存或外传整份配置。具体装载机制以 [ego 插件与 DSH 原始资料](../knowledge/sources.md#s27) 为准；未实测配置前不归咎模型。

## 确认可用性

1. 在当前 shell 确认命令能否解析，PowerShell 可用 `Get-Command ego-browser`。找不到命令时，先检查安装目录和本会话的 `PATH`。Windows 默认安装目录可用 `%ProgramFiles%\Citro Labs\ego lite` 定位，在默认 C 盘系统上即 `Program Files` 下的对应目录。检查进程 `PATH` 是否为空或缺少实际可执行文件所在目录，必要时对照用户级和系统级 `PATH`，再判断是否与沙箱过滤或会话未刷新有关。命令查找失败只说明当前会话无法解析入口。确认已安装时，可在权限允许的会话中用现场定位的可执行文件运行，或在新终端重新检查 `PATH`。
2. 执行 `ego-browser skill`，确认命令成功返回且指南完整，末尾应有 `[ego-browser:skill] end of guide`。按指南直接读取本次目标页面，需要图片证据时截取该页，不另做空白页截图。若截图提示窗口已最小化，恢复 ego 窗口后再试。
3. 记录实际入口、目标页读取结果和遇到的错误；命令失败时再记录相关安装与 `PATH` 检查。指南成功只验证命令入口，不代表账号已登录或目标页面可读。

## Windows PowerShell 5.1

Windows PowerShell 5.1 调用原生程序时可能丢掉 `-e` 参数内部的双引号。多行脚本或含中文的脚本一律用宿主文件工具写成 UTF-8 `.mjs` 文件，再按 `ego-browser skill` 返回的文件执行方式运行。不要用 `Set-Content` 或 `Out-File` 写脚本。

## 一次最小真实读取

这一步只确认入口和页面条件，不能作为运营调查完成的标准。

1. 打开目标页面，核对当前账号、地区和登录状态。无法确认的条件记为“未知”。
2. 等目标内容渲染后，用 ego 的 `snapshot()` 读取可见正文和控件。使用其他浏览器时采用对应的页面读取能力。
3. 截取同一页面状态，记录观察时间和时区。若只看到局部内容，注明截图和正文覆盖的范围。

没拿到正文就记录“未取得正文”，并注明卡在加载、登录、访问限制或读取工具的哪一环。没有观察到的内容不能写成“页面无内容”。

## 把浏览器用于运营调查

带着会改变动作的问题进入页面。例如“这个词吸引的是购买者还是同行”“从内容到试用是否存在可用入口”。按相关平台卡确定先看什么，不固定搜索词数或打开篇数。

- 搜索调查先核对原生搜索与排序条件；联想、相关搜索和用户原话是扩展线索，实际出现的表达与自行提出的候选词分开记录。
- 打开相关原内容和评论上下文，核对场景、作者/评论来源类别、日期、产品条件及可见承接入口。账号身份不能仅凭自称确认为买家，不收集个人联系方式。
- 用观察决定下一次读取。同行广告多则追查用户问题和替代办法；评论暴露新场景则查对应表达；爆款结论需比较普通内容和反例；经营下降则查对应后台环节，不能只看公开播放。
- 每轮只留下会影响决定的“查看目的 / 实际观察与证据 ID / 当前解释 / 下一步”。截图和调用次数不能代替正文理解；同一页面的重复读取不算独立证据。
- 证据足以制作内容或开展低风险实验时就进入执行；关键缺口仍可取得时继续。具体停止和转向条件见 [运营执行](operations.md)。

失败时分别判断命令发现、指南加载、浏览器连接、目标页登录/权限、渲染和正文读取。工具失败不等于业务结论。沿入口顺序换现有能力，或取同一原来源的公开资料；需要用户配合时一次说明具体页面与必要字段。已能完成的分析和草稿继续完成，不能虚构未读评论或后台指标。

## 多个环境与账号核实

用户要求操作其多账号时，先按当前 ego 指南及必要的主题帮助发现已有环境、环境唯一 ID 和指定环境的能力。环境、任务空间、页面是不同对象；多个窗口或任务空间不证明有多个独立登录环境。不在公开仓库复制 ego API、选择器或本机连接配置。

1. 列出当前连接实际返回的环境 ID 与名称，和已运行任务空间的归属分别记。只用返回的 ID 选择环境，不猜名字对应的 ID。若用户使用独立服务，按当前 CLI 帮助与用户提供的服务入口核实，不靠扫描端口、窗口顺序或自动试名找账号。
2. 明确选择一个环境，验证返回的空间归属确实是该环境。当前版本如只在创建空间时接受环境选择，就为用户要求的各环境各用一个空间；后续按对应空间 ID 恢复，不向已有空间传另一环境参数冒充切换。单环境内继续复用页面，不每篇新建空间。
3. 从该环境的“我”或账号信息页核对当前登录者的可见名称及可区分的账号号/主页 ID，再核对创作后台身份。打开任意作者主页不证明这是当前登录者；同名、站点差异或后台身份不清时保持待核实。
4. 在业务现有 `TOOLS.md` 保存最小映射：`本地账号代号 | 站点 | 环境ID/名称 | 当前账号名及可区分标识 | 身份来源/时间 | 可读与可写范围 | 证据路径`。实际服务入口仅在需要时加列，任务空间/页面标签记在任务中，它们不是永久环境 ID。不保存 Cookie、口令或完整私人配置。
5. 每次写入前重新核对该环境当前账号与分配目标；重命名不改账号身份，重新导入或重新登录可能改变映射。映射不符就停止该账号并记录，其他已就绪且获准的账号可继续。不能为了“凑齐账号数”新建环境、代发或自动登录。

环境列表为空或只有一个就如实记录；单环境成功只证明该环境能力。原始截图、账号标识、环境 ID、连接入口及执行脚本全部放私有业务目录，公共示例只用合成数据。

### 首次导入由用户完成

导入与登录沿用 ego 现成功能，不开发导入器或复制凭据。先看安装版本的 `ego-browser import --help`；`ego-browser import list` 列出的是**可导入的来源**，不能当成已导入 ego 的环境列表。

2026-11-16 本机帮助支持 Edge，要求每个浏览器块只有一组 `--profile`，多个来源目录名列在该组中。例如 `ego-browser import --browser edge --profile Default "Profile 1"`；不使用重复 `--profile` 的推测写法。目录名来自实际列表，不等于界面昵称。版本变化后重新查帮助。用户准备好并关闭来源浏览器后自行导入、命名和验证；Agent 不擅自关闭浏览器、清空旧环境或执行导入。

## 发布、预约与中断恢复

用户说“分配这些内容”先做本地分配，只有明确发布授权才提交。复用已审核版本，不每篇重复审核；审核、账号分配与发布授权分别记录。已有授权覆盖同一批版本、账号与范围就直接执行；修改了内容或目标只补确认受影响的部分。

- **先检查成品**：实际图片文件、数量/顺序、标题、正文、标签与产品事实。打开图片确认可读；纯文字或图片说明不是图片。按本业务账号定位分配，检查相同内容是否已发和批内高度同质化；不给同一内容换个标题就当新稿。账号不足时保留未分配项，不自动挤到其他账号。
- **再进指定编辑器**：核实环境、前台及后台身份、站点与获准范围；上传图片，填写信息，检查最终缩略图、图片顺序、标题正文与预览。文件输入框出现文件名不证明上传完成，输入框有值也不证明应用已接收；计数或预览未更新就核对输入事件并使用当前工具支持的正常交互，不能直接宣告填表成功。
- **提交前落盘**：在原任务写明内容 ID/版本、目标账号和环境、方式、具体日期时间及时区、授权来源、当前状态、核对时间。一次只处理一项对应关系，避免混用另一环境的页面/选择器。临时上传可能产生平台草稿，记录测试稿及是否保留，不操作其他草稿。
- **核对平台结果**：提交后读成功提示、管理列表、状态和可取得的笔记链接，核对账号、内容、版本及时间。审核中只记平台实际状态；没有明确依据就记“状态未知”。拿不到链接时写未取得，不编造。发布状态与实际经营效果分开。

任务内每项使用以下状态，保留审核与授权来源字段，不因状态文字自行创造权限：

| 状态 | 成立条件及下一动作 |
| --- | --- |
| 已制作 / 待审核 | 图片及文字已真实完成；未过审核就不提交 |
| 已审核及授权 | 对应版本、账号及执行范围都有明确依据；仅审核通过但未授权发布时仍等待该动作授权 |
| 提交中 | 提交前已保存，正在执行；不是成功 |
| 已确认发布 | 平台明确确认发布并与目标匹配；平台审核中不得升级为已公开可见 |
| 已确认预约 | 平台明确保存了目标账号的具体预约时间；不是实际发布 |
| 发布失败 | 平台有明确失败依据；保存原因与已完成步骤 |
| 状态未知 | 超时、中断或返回矛盾；先读平台，不盲目再次提交 |

“继续剩下的”先读原任务与当前映射。已确认发布不重发；已确认预约先查队列，不再当未发布项补发；提交中/状态未知先用平台列表、标题/时间/预览等核实。可唯一匹配就补状态和链接；有多个相似项或确认不了就保持未知，不凭标题相同认领。只有确认未发布且原授权仍有效，才继续原动作。中断不能把本地旧的“待发送”覆盖平台新结果。

### 只使用平台原生预约

在目标账号实际编辑器检查预约开关、日期时间选择器、允许范围与时区。把“明天”解析成具体日期；只有“上午/下午/晚上”且缺少约定时段、会影响提交时，集中补问一次具体时间，已明确就不重问。平台时区未明时先核对，不把浏览器时区当作平台已确认的时区。

设置时间后核对回显，按获准动作提交，再从平台取得预约确认；仅出现控件、填好时间或按钮改名都不算预约成功。界面不支持、时间不可选或权限受限就保存配置及原因，不另建后台定时脚本。平台预约是这次会话提交的原生任务，不代表 GoFind 常驻运行。

## 按账号读取后台与复盘

恢复映射并重新核实身份，进入该账号可见后台。先核对用户要求的具体起止日期、时区和筛选；“最近七天”按页面实际窗口记录是否含今天及数据延迟，不能拿全部时间的数量冒充。逐个账号、笔记与内容主题保存实际字段、口径、观察时间和证据，沿用 [数据判断](../knowledge/methods/measurement.md)。

账号可能有不同字段或访问范围。界面没有曝光、咨询、来源等字段就记未知，不用收藏/评论换算咨询与付款。微信人工咨询、试用和实收由用户真实记录补齐，关联依据不足就保留归因未知。一个账号受限不抹去其他账号数据，不为缺失指标重做全套市场研究。

给下一批内容的取舍说明依据：相关用户问题/咨询、真实试用和付款分别看，结合制作投入；只取得互动时只能判断互动。记录回原任务与索引，下一次制作直接复用。没有可访问的数据面板或近期内容时，明确本次取得了什么及还不能回答什么。

## 取证字段

沿用任务内的证据 ID，记录实际使用的入口、原样查询和观察范围。[证据登记](evidence.md#实际登记不做数据仓库)

- **来源与原件**。页面 URL、标题和截图相对路径。公开笔记按原样保留封面、正文和必要的评论语境。截图放在 `workspaces/<business>/tasks/<task>/`，路径相对于项目根目录。
- **观察条件**。登录状态、地区、视口尺寸、排序与筛选。条件未确认时标记“未知”。
- **观察时间与结果**。时间及时区、实际取得的正文或可见元素、截取范围和未取得的字段。用户提供的截图或导出注明来源。

## 授权与隐私

- 对平台或账号执行任何写操作，包括发帖、评论、私信、下单、改价和改设置，都必须有针对该动作的明确授权；已有明确授权在约定范围内持续有效。只读搜索的输入、筛选、翻页和本地草稿/证据保存直接推进，不把这些交互当作对外发布来反复确认。
- 需要登录或处理验证码时，用 ego 的 `handOff()` 把控制权交回用户，用户完成后再继续。降级到其他入口时也由用户处理登录和验证码。不得绕过访问限制或导出 Cookie。
