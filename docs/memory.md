# 用文件延续业务，不把所有内容塞进上下文

本地记忆依靠 Agent 的标准文件读写与搜索，不需要数据库、额外模型或私人 Skill。没有实际需要保存的短任务可以直接完成；有价值的事实、判断、产出和结果才进入记忆。

## 一个业务的最小目录

```text
workspaces/<business-id>/
  PROFILE.md                 # 产品、用户、目标、资源、边界；标明资料状态
  INDEX.md                   # 每个有价值任务一行：日期、问题、发现、路径、复查条件
  tasks/2026-11-10-短主题.md   # 同一任务里的证据、判断、产出、执行与复盘
  tasks/2026-11-10-短主题/     # 仅在需要截图/导出等附件时建立
  LESSONS.md                 # 仅在有经验值得复用时建立
  TOOLS.md                   # 仅在需要复用工具入口时建立；不保存登录信息
```

`business-id` 选稳定、简短的目录名；业务中文名称写在档案中。不同业务的资料不互相复制为事实。共性经验可以抽象成方法，但去掉身份信息，并注明原来适用的条件与新业务尚需核查的地方。

用户说明长期业务或同一业务出现第二次任务时，Agent 按 [业务模板](../templates/business.md) 主动建立档案和索引，不要求用户手动建目录。本地保存属于任务内可逆工作，不逐项请求许可。单次改稿不建档；首次研究或实验有会改变后续动作的结论时，保存最小业务档案、任务与索引，不保留不适用的空栏目。

## 开始新任务时读什么

同一会话先用已有上下文继续，只读本轮变化、确有冲突或已遗失的信息；不因每次收到新消息就重复建档、全读方法或要求再确认。跨会话或上下文丢失时，先确定业务，再读 `PROFILE.md` 和 `INDEX.md` 当前有效策略，从直接相关的少量任务恢复。没有历史资料就直接工作，不伪造“根据过往经验”。

续接时先恢复当前目标、主要渠道、上一动作的真实状态、观察窗口与未解决问题。草稿不能当已发布，待执行不能当已测试；缺少结果先检查已有工具/快照，取得结果再决定继续、调整或停止。对尚未成熟的退款、核销或留存窗口继续保留“待观察”。

对经验重新判断适用性：产品/客群/价格/平台规则/履约或测量方式变了吗？规则和平台现状在依赖它们作新决策前复核；一次实验结果是历史事实，有效性外推仍是推断。日期较新也不自动代表可靠。

## 方向变化只改受影响的部分

用户最新明确决定更新本业务当前策略，在原档案/索引写明变更来源、替代哪项决定及现在做什么；同日多次变更要写清先后，不能仅按文件日期猜最新项。历史研究、当前决定、实际结果和待办分别看，旧授权不让已经取消的动作自动恢复。

沿当前任务找到受影响的执行清单、待审核页、台账与后续跟进：明确标记“暂停/取消、原因、被哪项策略替代”，移出待批准/待发送项；历史正文保留作参考。只暂停某条路径时，不删对应客户问题和原件，不把它写成所有业务的限制。恢复须有新的明确决定，不因旧文件仍写“待授权”就再提请批准。

档案中已确认的产品、价格、支持条件与实测沿用；缺少新的截图/录屏不制造事实冲突。只改变化的字段与任务，不重建项目或将全部历史降成待验证。

## 产品事实改变时主动修订

发现当前产品类别、功能、报价或测试经历与旧档案不符，先记录新来源与日期，更新当前 `PROFILE.md` 和 `INDEX.md`；确有冲突的字段保留差异并定向核对。用户明确纠正的现行报价可直接作为新的工作条件，不沿用旧价或自行补授权周期。

在修订任务列出“旧前提 → 新事实 → 受影响结论/文件 → 已替代或待复核 → 下一动作”。沿索引和关键词搜索相关客群、竞品、价格、内容与经验，给受影响的旧任务和待发布成品加状态及新任务路径，保留旧原件。只影响一部分就保留其他有效观察；不得静默删除失败研究，或因本轮局部阅读把旧实测降为不存在。没有推送或外发授权时修订限本地文件。

## 任务结束后留下什么

任务文件中给重要结论引用证据 ID，明确实际已执行、仅完成草稿、待授权或当前受限。内容产出直接写入任务或链接业务目录内的成品。保留必要原件、来源、观察条件和缺口即可，不沉淀整页低价值搜索结果。

多账号的环境/账号对应关系复用业务 `TOOLS.md`，执行状态放原任务，按[浏览器说明](browser.md#发布预约与中断恢复)记录每项版本、目标、授权及平台确认。提交前保存“提交中”，中断后先核实平台再更新；不重发已确认发布或预约的内容，不把未知改成成功。取消项继续保持取消，不因旧清单或旧授权重启。

持续内容经营时，在档案按需保留“希望客户形成的判断 / 当前内容路线 / 相关任务”，任务中记录真实问题、观点依据、切口与成品版本、系列中的独立作用、实际反馈和成本。认知目标、已观察的用户理解与商业结果分开；不要仅记栏目名或爆款标题。短期成交或单条改稿不为此建立内容规划文件。

下一轮从尚未回答的客户问题、已有证明和反馈恢复，而非每次重做全套系列。主题变了但仍能证明同一价值可以保留；高播放却偏离目标客户、专业表述被误解或制作成本过高时，记录触发依据并调整。旧实验保留状态，不把规划冻结成固定比例或排期。

`LESSONS.md` 每条包含“方法 / 适用条件 / 实际结果与证据 / 反例或混杂 / 暂定或重复支持 / 复查触发”。一次成功先标暂定；多次成功仍不能自动跨平台外推。被否定的经验加失效原因和日期，索引指向新结论，不能只删掉失败记录。

## 写什么、不写什么

记忆的目标是“下一次还能用”，不是“这次全留”。

| 值得写 | 不值得写 |
| --- | --- |
| 业务事实：产品、客群、价格条件、可服务范围 | 完整聊天记录、对话原文粘贴 |
| 一次任务的来源、观察条件、口径与截图 | 整页网页归档、整份后台导出 |
| 已验证事实 / 分析推断 / 待验证假设 | 反复推翻的中间草稿 |
| 可直接使用的成品：标题、正文、脚本、报价 | “我打算写一个……”的计划 |
| 结果与未执行项：发了没发、测得没测 | 同一结论换三种说法 |

拿不准时只问一句：这条会改变下一次任务的某个决定吗？不会就不写。

## 按变化更新，不强制改三处

1. `PROFILE.md`：业务事实或当前主线变了才改（目标、阶段、主要渠道、价格、客群、容量、授权范围）；指向具体任务，不堆历史。
2. `INDEX.md`：加一行——`日期 | 问题 | 结论与状态 | 任务路径 | 复查触发`。
3. `tasks/<date>-<主题>.md`：保留证据、判断、成品、已执行动作、实际结果、未完成项和复查条件。持续实验可在原任务按日期追加快照，不为每次观察创建一套文件。

有可复用结论就保存任务并更新索引，即使档案无需变化也照常记录。没有可复用结论的短任务不记。不为凑结构建空文件、空小节；[任务模板](../templates/task.md) 按需删减。

经营快照按需用任务内 Markdown 表或轻量 JSON/CSV，记录期间、时区、对象/渠道、分子分母、成本和退款/核销成熟度。新快照保留旧口径与差异，不把不同窗口直接拼成趋势；不默认建设数据库或保存整份后台。

复查写明触发事件或日期、要取的结果和继续/调整条件。在当前会话可完成就继续；未来无人值守复查需要宿主调度器并实测配置。本地文件里的计划不代表定时执行已启用。

## 索引不长胖

历史结论是历史事实，不外推为当前结论。索引长到无法一眼扫完时，先合并同类项；已失效的行标为“已失效（原因、日期）”，半年未复查且不再影响动作的记录移到 `tasks/archive/`，索引留一行指向新位置。标记和归档可保留判断依据，直接删除会丢掉它。

## 保存的边界

`workspaces/` 和 `private/` 全部被 Git 忽略；任何真实业务、未发布素材、工具导出和授权记录都放这里。不要在项目根目录随手保存客户数据；外部来源中的访问令牌和联系方式也要去除。公开示例只含主动选取的公开、非敏感信息，不从私人业务自动导出。

这些目录没有加密，也不会自动云同步。用户需要备份时按明确选择的备份位置操作；复制整个项目到另一台电脑可连同这些本地文件迁移，公开仓库的普通克隆则不包含它们。不要把“Git 忽略”说成已备份或绝对不会泄漏；被强制添加的文件仍可进入 Git。
