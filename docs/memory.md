# 从业务当前状态续接

持续业务、同一业务的第二次任务或产生可复用决定时，在 `workspaces/<business-id>/` 放业务档案、索引和已有任务。会话内延续已知信息。跨会话读 `INDEX.md` 当前段和它指向的原件。获客选题、写稿和审稿还要读 `PROFILE.md` 的主需求和购买理由。其他续接任务在索引和当前原件足够时直接执行或报告阻塞。出现事实缺口、冲突或复查请求再查历史。旧索引没有当前段时，从明确采用的版本与业务方决定恢复，有依据后补当前段。状态照旧时直接引用原来的记录。[业务模板](../templates/business.md)

| 文件 | 写什么 |
| --- | --- |
| `PROFILE.md` | 长期产品事实、主要功能、报价与条件、目标、客户及已确认的主需求和购买理由、有效策略和工具/账号条件。附原始依据。方向变更注明替代了哪个决定 |
| `INDEX.md` | 一个当前瓶颈、一个准确版本与原件、实际执行状态、仍缺条件、唯一下一动作、主要结果或复查触发。下方只留能改变下次决定的少量历史导航 |
| `tasks/` | 保留原始研究、旧版、真实执行结果与必要附件。一个任务可容纳调查、成品和反馈。审计或模拟材料退出真实业务的活跃导航，历史路径可继续回查 |

账号映射按需沿用 `TOOLS.md`，可复用的运营经验按需放业务 `LESSONS.md`。单次改稿或没有复用价值的工作可以只交成品。

## 用索引决定用哪个版本

索引顶部写稳定版本 ID 和原件链接。成品入口给出正文及图片顺序，必要的证据跟随原任务。`draft` 是在编辑的草稿，`candidate` 是已送审的成品，`approved` 是内容审核明确通过，`published` 要有平台确认。实际触达、预约、观察和效果另以动作结果写在同一处。内容审核和外部动作授权分别核对。

版本接替时更新索引当前指向。在原任务留下 `superseded → 新版本` 或 `retired` 及原因，旧内容和原件留存。当前可用版本以索引为准，历史标题、修改时间和旧审批包只供追溯。可以合并旧索引条目，先保留老索引或原有证据入口。多账号队列在原任务保留逐项状态与平台确认，公共当前段可直接指向该任务。[发布中断恢复](browser.md#发布预约与中断恢复)

## 只修真正变化的事实

找到新来源和日期后，更新档案中该字段。原任务记一条“旧值 → 新值和依据 → 停用的承诺及受影响稿件 → 仍有效的事实”。从索引指向的成品和报价查该字段，有具体影响再补查关联任务。改已审核或已发稿里的报价、适用条件或承诺时，复制完整原稿，只替换受影响的文字或页面，复核其他正文、素材和实测仍在。索引指向待审修订稿，原稿、审批和回执原样保留。

用新证据补充场景、证明和表达。只有证据足以改变目标客户要做成的事或选择产品的原因，才更新主需求或主卖点。先在当次任务记下原件、新旧决定和受影响的稿件，再把采用的决定及依据写入 `PROFILE.md`。仍待验证的方向留在当次任务。

用户改变方向时，在档案记现行策略并从索引撤下被取消动作。若有正在执行的队列，另在队列标取消。历史批次仍可回查，旧授权只适用于其对象、版本和已获准动作。

## 记下用得上的结果

给会改变决定的事实留下来源和原件，给实际动作留回执。成品状态引用原件，索引只链接下一轮需要打开的内容。已经有记录的调查和预检直接引用。被推翻的判断可保留原话并附新依据。等待外部动作、数据缺失与确实观察为零分别写明。[任务模板](../templates/task.md)

经验需写清业务、实际动作、观察窗口、原始反馈、反例和适用边界。一次结果先标暂定，重复证据或反例决定保留、修正或撤下。公开研究出处放知识来源，与业务结果各按自己的依据使用。复查按实际事件或观察期触发，只有已经配置并实测的宿主调度才记为自动安排。

真实业务、授权记录、未发布稿和账号资料放在 Git 忽略的 `workspaces/` 或 `private/`。不保存密码、Cookie 或密钥。目录忽略只控制常规提交，备份和公开审查仍按实际环境处理。
