# 从业务当前状态续接

持续业务、同一业务的第二次任务或产生可复用决定时，在 `workspaces/<business-id>/` 放业务档案、索引和已有任务。会话内延续已知信息。跨会话读 `INDEX.md` 当前段和它指向的原件。获客选题、写稿和审稿还要读 `PROFILE.md` 的主需求和购买理由。其他续接任务在索引和当前原件足够时直接执行或报告阻塞。出现事实缺口、冲突或复查请求再查历史。旧索引没有当前段时，从明确采用的版本与业务方决定恢复，有依据后补当前段。状态照旧时直接引用原来的记录。[业务模板](../templates/business.md)

| 文件 | 写什么 |
| --- | --- |
| `PROFILE.md` | 长期产品事实、主要功能、报价与条件、目标、客户及已确认的主需求和购买理由、有效策略和工具/账号条件。附原始依据。方向变更注明替代了哪个决定 |
| `INDEX.md` | 一个当前瓶颈、一个准确版本与原件、实际执行状态、仍缺条件、唯一下一动作、主要结果或复查触发。下方只留能改变下次决定的少量历史导航 |
| `research/` | 需求调查、客户任务、购买动机、现有替代和原始证据 |
| `references/` | `REFERENCES.md`、参考原帖、必要截图和参考素材 |
| `production/` | 成品图片、正文、页序、逐页 `visual-review.md`、Job、生图和下载回执 |
| `publish/` | 发布版本、账号映射、授权与 `receipt.md`、评论或咨询入口核对 |
| `analytics/` | 曝光、来源、点击、咨询、试用、成交、成本和复盘 |
| `tasks/` | 历史任务和归档，默认跳过 |

业务新产物只进对应目录，按需建子目录。迁移时只复制当前有效版本及必要回执，旧文件留在原路径，原始证据可以继续用相对链接回查。旧 `TOOLS.md`、`LESSONS.md` 沿用原路径。单次改稿可以只交成品。

## 用索引决定用哪个版本

索引顶部用一个稳定版本 ID 和一个原件链接指向当前版本。引用或更新当前图文状态时，先核对该版本的单据，再从下表取一个状态。研究等尚无图文交付的任务只记进展。

索引状态只在这里定义；单据里每列填什么、缺画面怎么写，见[用工具结果确认实际动作](evidence.md#用工具结果确认实际动作)。

| 索引状态 | 对应单据与条件 |
| --- | --- |
| 待目视 | 缺当前成品的 `visual-review.md`，逐页表有空行、缺页或空字段，页序、文件名或 SHA256 不符，或任一页缺实际观察、结论为「待看」或「要重做」。[单据条件](evidence.md#用工具结果确认实际动作) |
| 可审核 | `visual-review.md` 每页都有实际观察，页序、文件名与 SHA256 对得上，各页结论均为「能上」。缺真实发布回执或只有 `TEST` 回执时停在此状态。 |
| 已发布 | 逐页单据达到「可审核」条件，且 `publish/` 下对应提交目录有真实 `receipt.md`。核对账号、平台、笔记链接、提交时间和平台截图原件，确认平台已发布的确为这次提交的同一版本。 |

用[交付单据模板](../templates/delivery-evidence.md)建立单据。内容审核和外部动作授权分别核对。审核中、预约、触达和效果记在各自记录里。

版本接替时更新索引的当前指向，在新记录写明接替关系和原因。历史标题、修改时间和旧审批包供追溯。多账号队列的逐项状态和平台确认放在 `publish/`。[发布中断恢复](browser.md#发布预约与中断恢复)

## 只修真正变化的事实

找到新来源和日期后，更新档案中该字段。在本次动作的目录记录旧值、新值、依据和影响。从索引指向的成品和报价查该字段，有具体影响再补查关联任务。改已审核或已发稿里的报价、适用条件或承诺时，在 `production/` 复制完整原稿，只替换受影响的文字或页面，复核其他正文、素材和实测仍在。索引指向待审修订稿，原稿、审批和回执原样保留。

用新证据补充场景、证明和表达。只有证据足以改变目标客户要做成的事或选择产品的原因，才更新主需求或主卖点。先在当次任务记下原件、新旧决定和受影响的稿件，再把采用的决定及依据写入 `PROFILE.md`。仍待验证的方向留在当次任务。

用户改变方向时，在档案记现行策略并从索引撤下被取消动作。若有正在执行的队列，另在队列标取消。历史批次仍可回查，旧授权只适用于其对象、版本和已获准动作。

## 记下用得上的结果

给会改变决定的事实留下来源和原件，给实际动作留回执。成品状态引用原件，索引只链接下一轮需要打开的内容。已经有记录的调查和预检直接引用。被推翻的判断可保留原话并附新依据。等待外部动作、数据缺失与确实观察为零分别写明。[任务模板](../templates/task.md)

经验需写清业务、实际动作、观察窗口、原始反馈、反例和适用边界。一次结果先标暂定，重复证据或反例决定保留、修正或撤下。公开研究出处放知识来源，与业务结果各按自己的依据使用。复查按实际事件或观察期触发，只有已经配置并实测的宿主调度才记为自动安排。

真实业务、授权记录、未发布稿和账号资料放在 Git 忽略的 `workspaces/<业务>/`。不保存密码、Cookie 或密钥。目录忽略只控制常规提交，备份和公开审查仍按实际环境处理。
