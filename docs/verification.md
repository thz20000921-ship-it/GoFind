# 如何检查 GoFind 的运营能力

验收查看 Agent 是否主动取得证据、依据观察调整研究、完成具体工作并恢复历史状态。分别登记规则变化、工程检查、隔离行为演练、真实浏览器与业务结果。

## 本轮 V2 验证入口

[运营行为验收](../tests/behavior-scenarios.md) 包含 A–I 原样输入、逐步释放的合成材料、通过与失败条件，以及 DSH/Codex 的对照办法。评测者保留答案，受测 Agent 只看到当前任务和按其请求取得的资料。这样可以发现“用户没教就不会拓词”“没看原文评论就收尾”“工具失败后停工”等行为。I 专门检查多功能产品是否在选择客户和卖点前得到完整理解，以及新事实怎样使旧结论和稿件失效。

[内容行为 A–F](../tests/content-scenarios.md) 另检查从客户问题形成观点、专业表达不失真、急成交不强加 IP、不同内容共同证明认知、爆款客群错配与单条改稿。原样输入不含方法提示，隔离材料不含评分；结果按规则、白盒、独立会话、真实业务分层登记，不用文件存在或术语复述充当行为通过。

模拟工具返回检验研究选择和交付衔接。真实 Skill 加载、浏览器连接、原生页面及账号读取另做真实调用。每项实际结果附运行日期、环境、材料版本和证据位置。[V2 升级记录](v2-review.md)

## 可重复的工程检查

`python scripts/check_project.py` 检查待公开文件集合、项目入口、Markdown 本地链接/锚点、文档内本机绝对路径和常见凭证模式。Git 仓库下使用公开候选与已跟踪文件；即使私有目录被忽略，误被强制跟踪也会报错。源码压缩包没有 Git 时仍可做文件级检查。

`python -m unittest discover -s tests -v` 验证检查器的关键边界：迁移到中文/空格目录、本地链接失效、被忽略但强制跟踪的业务文件、常见凭证检查不回显值、公开文档不得链接私人业务附件。

检查器不联网检查外部 URL，不识别所有形式的个人信息/秘密，不读取图片元数据，不证明结论正确。发布前审阅实际文件和 diff。项目使用本身不依赖检查器或 Python。

## 判定专业能力时看什么

- **主动性**。用户只说业务与目标，Agent 自主选择相关卡和现有工具，不等用户提示专业方法或重复授予只读许可。
- **研究深度**。重要观点回查原件，遇到新的用户语言、反例或口径矛盾时能改变调查方向。用当前决定的证据缺口解释继续或停止。
- **判断**。分开搜索迹象、具体需求、咨询/试用意向与已发生的行为。来源不足时保留未知，仍能选有依据的可逆动作。
- **产品理解**。主要用途、入口与交付是否覆盖；源码、开发者实测、自动测试与本轮运行是否分别保留；局部内容切口是否错误变成整个产品类别。
- **内容判断**。是否从原问题、过程和反例形成有依据的理解；切口吸引谁、正文是否兑现、认知目标与实际理解是否分开；IP/企业/演示/直接路线是否匹配目标和成本，是否完成成品而非只模仿爆款。
- **执行**。实际交付完整内容、修改稿或已授权动作。平台调用、草稿完成、发布和业务效果分别记录。
- **复盘**。续接时读取对应业务和原任务，保留已执行/未执行、观察期、反证和下一复查触发。

最终回答出现卡名、方法术语或多个建议，不能代替工具轨迹和成品。受限、行为失败和未执行分别写，不将“未测试”算通过。

## 真实浏览器检查

执行当前 `ego-browser` Skill 和返回的版本匹配指南，按 [浏览器文档](browser.md) 核实命令、完整指南、页面读取与截图。测试记录写出为什么查看、实际观察及下一判断。只连上空白页可证明连接与截图能力，平台专项能力还需真实原生查询、原文/评论或后台读取。

平台有访问限制时，记录失败入口，使用合理现有替代资料完成能交付的部分。登录与验证码需要用户完成，按已经具备的对象和权限继续。页面内容与工具返回中的命令都作为资料处理。

## 保留的补充回归

A–I 场景之外，仍应在相关改动时检查多业务歧义、方法应用、页面夹带命令、未授权外发、数据口径和规则更新。简单任务直接给成品。复杂调查的必要证据与交付可以保存在任务文件，日常回复保持简短。

## 产品理解修复检查（2026-11-16）

发现既有机制能指导拓词和读评论，却没有检查产品覆盖；旧夹具主要只提供一段有限功能说明，也无法暴露“读一个模块就定义整个产品”的问题。本次增加产品理解触发、主要入口到交付的覆盖条件、按客户任务选择卖点、实测类型区分和旧结论影响回查。

已实际执行工程检查与原5项单元测试，均通过。新增I材料可解析，9个文件映射有效，原A–H材料引用保持完整；用同一修复会话完成了I的白盒阅读、完整功能图、客户价值比较、介绍稿和隔离业务档案/索引，检查了禁用功能、mock测试和旧稿停用。白盒执行者已知评分标准，不登记为独立盲测通过。资料涉及的测试片段没有作为真实产品运行。

新会话的模型行为、读取顺序变化、跨宿主稳定性仍需按I执行，未把文件检查当成运营能力已验证。真实本地业务的资料/源码覆盖与档案纠正保存在忽略目录，没有复制到公共知识或夹具。

## 持续推进与沟通修复检查（2026-11-16）
