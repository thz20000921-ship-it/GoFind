# 证据怎样支持运营判断

证据的来源、访问完整性和结论性质是三个维度。不要用一个“可信度 95 分”掩盖差异，也不要要求每条日常润色建议都做研究报告。

## 先界定这个来源能证明什么

| 来源 | 可以支持 | 单独不能支持 |
| --- | --- | --- |
| 平台官方规则/指标文档 | 该版本公开规则、指标定义 | 某个账号一定能获得流量或盈利 |
| 实际打开的搜索结果/内容/评论 | 观察条件下出现的内容与表述 | 全量搜索量、所有用户需求、净成交 |
| 商家官网、广告、自述案例 | 该商家做出的主张、展示的价格条件 | 主张已独立证实、广告赚钱、同行打法可复制 |
| 用户提供的业务描述 | 用户目前的说法与目标 | 产品效果、订单真实性已核实 |
| 已授权的订单/结算/咨询原件 | 对应对象、时期与口径的实际记录 | 规模化可行、渠道增量贡献或长期因果 |
| 方法论文、研究原作者、可信行业研究 | 原样本与设计下的发现 | 直接迁移到不同平台和业务的效果 |
| 第三方工具估算 | 工具定义下的估算值或方向 | 平台全量真实值或本业务确定收益 |

只看到摘要就写“摘要”；页面空白写“未取得正文”；未取得的指标写“未知”。截图、局部正文和录屏片段要说明截断处，重要结论尽可能核对完整上下文。多个转载同一原件不算多个独立证据。

## 三类结论

- **已验证事实**：可回查原件，在范围内核实。例如“这三条已打开的内容里有两条包含价格咨询”，不能扩大为“多数目标用户愿意付费”。引用证据 ID、样本与观察日期。
- **分析推断**：证据支持但尚不能直接证明的解释。例如“价格信息不清可能导致咨询流失”；写出替代解释，如人群不符、入口故障、样本偏差。
- **待验证假设**：尚缺证据的预期。例如“补一个实际使用演示可以提高有效咨询”；写明如何测试、什么会否定它。

官方来源也要看适用地区、业务类型、发布时间和是否已经生效。用户原话可以证明“有人这样说”，不能自动证明原话描述的效果。研究者自有案例和供应商案例各自标记利益关系。

## 实际登记，不做数据仓库

在对应业务的任务记录中，用 `任务代号-E01` 等稳定 ID 写：

```text
来源：原链接/本地原件相对路径、发布者或来源类别
观察：观察时间及时区；原文发布时间未知则写未知
工具与方法：实际工具、原样查询、筛选/排序、访问范围
样本与口径：观察了哪些对象、如何选择、计数单位、期间
事实：只写实际读到/看到的内容；短摘录保留上下文
限制：缺什么、个性化、选择偏差、商业利益、无法核实的部分
支持：它可以支持哪个有边界的判断；不能推出什么
```

原件只保存需要复查的部分，保留原来源和必要上下文，不整站归档。含身份信息先脱敏；无法合法保存的原件只保留访问说明与链接。证据 ID 不因调整排序而改变。

## 遇到冲突或“机会”信号

先核对是否同产品、规格、地区、人群、流量来源、时期、退款口径与计数单位。区分后台记录、展示估算、商家宣称和引用转述。不把不同口径简单求平均。

为当前主张主动寻找一个能推翻它的观察方向：没有购买的人怎样解决问题、失败内容在说什么、低价竞品是否足够、曾经有效的方法如今是否失效。样本不是越多越好；重复相同信息时，检查是否还有会改变行动的缺口。

小样本可发现具体问题，通常不能估计总体比例。空白结果不证明没有需求；高互动不证明愿意买。既不要过度推广一个样本，也不要因此丢弃样本真实呈现的问题。

## 从证据进入行动

证据已足以选择可逆测试时，交付或执行测试；不要等待“完全确定”。若剩余未知会改变预算、交付能力、授权或不可逆后果，先补这个具体缺口。调查停止的理由可以是继续查不会改变动作，也可以是当前获取路径受限；两者都不能写成“市场已验证”。

实验必须记录预期与实际的差异。上线了文案不等于效果得到验证；找到询价不等于拿到客户；单次增长不等于因果。新证据改变结论时附变更记录，不静默覆盖旧判断。

上述为 GoFind 的判断方法；研究基础与边界见 [S01、S02、S07–S11](../knowledge/sources.md#市场用户与经营方法)。
