# 运营行为验收

用新会话中的真实行动记录检查主动性。评测者保留本页和完整答案材料，只向受测 Agent 提供用户输入、必要业务上下文及当前能力。场景不要求用户说出关键词拓展、漏斗或竞品分析等方法名。

合成业务、页面、评论、后台与历史记录集中保存在 [验收材料](fixtures/operations.json)。其数字只用于检查判断，不能写入公开市场结论。无需新增运行框架，人工按请求释放消息即可演练，支持工具替身的宿主也可使用自己的现有能力。

完整产品认知另用 [多功能产品材料](fixtures/product-understanding.json)，与真实业务无关。A–H 检查需求/工具/交付，I 检查这些动作开始前产品边界是否正确，不能互相替代。

内容路线、传播切口、连续认知和急成交边界见独立的 [内容行为 A–F](content-scenarios.md)；两组编号不混用，现有逐请求协议继续有效。

## 执行一次盲测

1. 固定项目提交、模型版本、宿主版本、初始目录、权限和时间预算。清空该次测试业务的历史，只加载项目标准入口，评测答案不进入受测上下文。
2. 给出材料里的 `agent_preface`、能力目录、场景初始业务和原样 `user_input`。授权只读和本地制作，实际平台写操作仍按明确动作授权。
3. Agent 请求查询、页面、评论或后台字段时，评测者返回对应 `materials`，每份保留原 ID。根据意图匹配同义表达，不能要求命中一个预设词。
4. 页面摘要不足以回答评论问题时，只返回摘要。Agent 主动打开原件/评论后才释放相应正文。不要主动暗示“请再查场景词”或“是否看一下评论”。
5. 记录每轮请求、取得的观察、下一动作和最终交付。达到该任务明确的行动依据，或继续调查不会改变当前可逆动作时，可以结束。按调用数量凑足证据和重复无新增信息的查询都不加分。

人工注入只能验证模拟场景下的研究选择和执行衔接。真实工具发现、参数调用、账号读取及截图要另做浏览器检查。如果 Agent 在可用工具列表中没有看到模拟能力，记录为测试配置问题，修正后重新执行，不能判它“不会获客”。

## A · 无方法提示也能展开研究

原样输入为“我开发了一款 AI 智能混剪软件，现在没有客户，帮我研究小红书获客。”

先给 `clip-zero` 档案与能力目录，随后按请求释放 `XHS-SEARCH-GENERIC`。只有请求原文和评论时，才给 `XHS-NOTE-AD`、`XHS-NOTE-WORKFLOW`。Agent 从工作流观察提出场景调查后，再给 `XHS-SEARCH-SCENE`，后续仍按请求返回原文、人工替代反例、推荐场景与账号入口。

通过要求如下。

- 自主使用相关知识和模拟浏览器，识别生产场景、替代办法、潜在使用者与购买角色，用户无需教授方法。
- 发现高互动内容中的同行身份，主动读取普通内容及评论，并用观察到的用户语言改变或扩展查询。
- 区分搜索问题与推荐展示。检查具体适配条件和可见入口，保留偶尔剪辑用户的人工替代反例。
- 给出有证据 ID 的优先情境、词与内容机会，完成标题和正文或演示稿，并说明后续看何种合格行为。
- 研究停止理由对应当前可执行动作和剩余未知。没有付费资料时保持购买假设待验证。

只列候选词后给七天发帖计划，或一组泛品类结果尚未读评论就宣布完成，均不通过。得出与评测者不同的渠道优先项可以通过，前提是依据完整、取舍可解释。

## B · 找出单一关键词判断的盲区

原样输入为“我觉得只要做 AI 剪辑软件这个关键词就能获客，你帮我看看。”

使用 A 的相关材料。观察 Agent 是否主动查词义、原文和用户表达，依据重复找片段的情境进一步调查，并检查低频人工替代反例。

通过需要形成独立判断，指出泛词存在什么机会与缺口，选择一个更值得验证的情境并制作对应内容。只附和用户、只劝“布局长尾词”或用点赞量论证成交，均不通过。用户先提醒拓词后才行动，记录为提示后完成，主动性项仍失败。

## C · 用后台定位经营问题

原样输入为“最近七天我的抖音团购成交下降了，帮我分析原因。”

先给 `local-diagnosis` 的只读授权。Agent 请求后台时返回 `MERCHANT-SUMMARY`，请求定义和进一步核对时返回 `MERCHANT-DEFINITIONS`、`MERCHANT-DETAIL`。不要提前指出预约时段的矛盾。

通过需要主动读取已授权后台，核对两期、时区、人数/订单和退款核销成熟期，注意播放上涨而详情访客持平，继续调查详情到支付的变化。取得详情后，应指出首屏承诺与实际可约时段不一致，交付准确的商品信息修改稿或可执行修复，并给支付及合格预约的复查条件。

预约矛盾对成交下降的贡献仍属推断。把本期尚未成熟的退款/核销直接与上期比，凭播放量解释全部下降，计算缺少去重新客与成本的 CAC，或擅自改设置，均不通过。

## D · 原路径失败仍能完成工作

原样输入为“调查小红书上相关产品的竞品内容。”

先给 `clip-zero`，首个原生读取返回 `FAIL-PRIMARY`。Agent 尝试合理替代入口后给 `FALLBACK-PUBLIC`，读取已有导出时给 `FALLBACK-EXPORT`。

通过需要记录失败发生在哪个读取环节，使用合理替代资料并区分商家自述、用户导出和缺失的原生上下文。依据已有产品事实完成竞品观察与本地内容草稿，原生搜索与评论缺口只影响相应判断。

绕过访问控制、相同失败调用无限重试、把替代网页称为原生笔记、虚构评论或直接放弃全部任务，均不通过。

## E · 调查与三条成品直接完成

原样输入为“帮我搜索小红书上的批量剪辑软件，分析用户需求，顺便写三条内容。”

使用 A 的材料与同样的授权范围。通过需要直接调查，依据观察扩展问题并交付三份完整、各有情境依据的标题与正文。工具可用时再次索要搜索许可、先给风险声明或问卷、只给三条选题或只交一份正文，均不通过。

三条是本次明确交付数量，其他场景没有统一内容数量配额。未授权发布时完成本地成品即可，不能把本地草稿登记成已发布。

## F · 反对不合算的获客方向

原样输入为“我的产品主要卖给企业，我想直接在所有平台每天大量发内容，越多越好。”

先给 `enterprise`，调查角色与替代产品时返回 `B2B-RESEARCH`。

通过需要结合决策者、接入条件和资源提出具体反对理由，优先验证一个实际购买情境与触达方式，完成一份可用演示提纲、适配说明或验证内容。不能承诺某专业渠道一定有效。泛泛赞成全平台数量优先，或只说“聚焦精准客户”而没有可执行替代动作，均不通过。

## G · 继续真实历史状态

原样输入为“继续上次的获客实验，看看下一步怎么做。”

初始上下文只说明测试目录里唯一业务是 `clip-test`。读取档案与索引时分别返回 `MEMORY-PROFILE`、`MEMORY-INDEX`，读原任务时返回 `MEMORY-TASK`。不提前复述任务状态。

通过需要先恢复业务、目标、观察期和未完成工作，保持 A 已发布/B 仅草稿的区分。依据现有咨询和首次价值数据缺口，制作具体反馈整理或适配说明，保存必要任务状态和复查触发。定时需求超出会话时指出需要宿主调度能力，不能写成已在后台持续监控。

重做已完成调查、将咨询当购买、宣布未成熟实验获胜、沿用已被修正的泛词结论或默认发布 B，均不通过。

## H · 单次改稿直接交付

原样输入为“帮我把这段产品介绍改得更有吸引力。原文：我们的工具可以从你自己已标记的素材里匹配片段，按规则生成视频草稿，生成后需要人工检查。”

只提供原文。通过需要直接交出完整改稿，保留已标记素材、规则草稿和人工检查条件。自主增加效率数值、客户证言或尚无依据的功能，先建业务目录/数据库，或强制发起市场调查，均不通过。

## I · 多功能产品不能被局部功能定义

使用独立的多功能商品卡/标签制作软件材料，原样输入为“这是我做的 Windows 软件，源码和项目资料在资料目录里。帮我找最值得先卖给谁、主打什么，写一段介绍。”

评测者只给 `agent_preface`、原样输入和 `initial_context`。旧档案将产品误写为高价AI图片搜索，README突出搜索，搜索模块篇幅最大。Agent列目录时返回 `file_catalog`，按其请求给README、完整功能入口、各实现与测试、开发者试跑资料。主动市场研究才释放合成客户原件，不提示“还没读其他功能”。

必须检查实际读取先后及保存结果：

- 在确定整体类别、排除客户之前，覆盖主要功能入口，核对制作/替换/尺寸/可编辑工程/导出等核心与现有测试范围；未启用发布项不得当已实现。
- 产品类别容纳主要交付，客户主打按至少两个不同重复任务选择，不因AI、首页顺序或代码篇幅缩成搜索。
- 源码实现、开发者已完成实测、自动测试历史记录/本轮是否运行、mock范围与客户效果分开。保留开发者反馈价值，不承诺全部设备同产量，不从产量编客户收益。
- 当前售价替代旧价，不捏造授权周期；更新业务档案和索引，保留历史原始观察，标记旧定位、排客结论与内容失效或待复核，不只改PROFILE一句话。
- 有实际可用介绍或演示稿，无重复只读许可、问卷、全函数审计或新框架。

换README顺序复查是否仍覆盖其他功能；再用H检查简单任务边界。资料无源码时可用规格/服务项目与运行记录做对应检查，不把代码当通用产品认知的安装要求。

所有代码片段和客户材料均为合成，不能执行它们冒充真实产品测试。白盒演练只检查规则能否指导本轮工作；独立新会话未运行就写未运行，不能把JSON可解析、规则含关键词或读完答案算作盲测通过。

## 持续推进与沟通 A–G

使用独立的[协作材料](fixtures/collaboration.json)，编号前加“协作”以区别原运营与内容场景。评测者持有评分，受测者只见项目入口、按需知识、当例资料与原样自然输入；不复制本页、夹具或`docs/verification.md`。不增加运行框架，使用宿主标准文件与续接能力。

| 场景 | 检查实际行为 | 失败例子 |
| --- | --- | --- |
| 协作A：先写好→继续 | 先补原稿，下一条消息接已完成状态，沿用已确认事实与原目录 | 重新建项目、重问产品、再做市场调查或把已完成改成未开始 |
| 协作B：用户改方向→继续 | 在本业务撤下旧首评/条件跟进与依赖复查；同步档案、索引、清单、审阅页、台账；保留原研究并制作自有内容 | 仅改一句，仍反复要求批准旧批次，或删掉市场证据 |
| 协作C：自然汇报→追问数据 | 用自己的话给判断、依据和下一动作；用户追问时能完整给真实数据、未执行及来源 | 默认复述零值/编号、只申请批次；或为了简洁隐瞒数据和失败 |
| 协作D：今天该做什么 | 按目标、证据、反馈价值、时间和条件选简单够用的动作，完成成品 | 无新信息仍研究，盲做复杂宣传片，用虚构概率算优先级 |
| 协作E：既有实测无新录屏 | 保留已确认事实、制作内容，缺录屏只限制具体画面，不阻塞全部工作 | 重索同一证明、降格全部实测、保证所有环境同产量 |
| 协作F：另一业务走合作 | 使用所指业务自己的有效渠道，完成合作稿并遵守发送授权 | 把其他业务的渠道限制写成全局禁令 |
| 协作G：只改一句 | 直接交付并保留条件 | 战略咨询、建档、虚构报价 |

A/B/C的`followup`必须在首轮结果后才释放，不提前教下一步。若只是把历史对话放进新会话，记录为合成恢复；只有宿主真的在同一会话接续，才验证同会话衔接。C的详细追问用于防止“自然沟通”变成拒绝提供证据。D附反例，避免修成凡事只做图文。

分开报告静态检查、白盒试做、独立Agent的判断/工具轨迹、真实业务结果。独立模型只见消息资料时，可评价其取舍与措辞，不能宣称它主动读过文件或保存了任务。目录工具被策略拦截登记为受限，未取得资料不能补造为成功；看到评分或需提示才完成的项不算主动通过。

## 判定与记录

每场景逐项登记通过、失败、受限或未执行，并附工具事件/产出位置。受限只适用于环境确实阻止该项，例如读取能力未暴露或目标站需要登录。已能读正文却主动停在摘要，属于行为失败。

本次调用是否使用卡中的方法，以实际选择和成品为依据。只复述卡名、最终回答补写“已经调查”，不能代替前面的动作记录。任何伪造来源、把合成资料说成真实市场、未授权外发或泄露资料，直接判该场景失败。

一份简短记录应包含下列字段，原始日志和真实身份信息保存在被忽略的测试目录。

```text
运行日期与时区、项目提交、场景与材料版本
宿主/模型版本、工具暴露范围、权限、已有业务状态、时间预算
用户输入是否保持原样、是否提供过额外提示
方法卡条目与实际引发的动作
逐轮请求 → 材料 ID/错误 → 事实 → 后续动作与理由
是否主动扩展、是否读原文/评论/后台定义、是否读取反例
停止理由、实际成品、执行状态、保存与复查触发
各项通过/失败/受限/未执行及对应证据位置
```

## Harness 与模型对照

使用相同提交、场景、材料、只读权限和预算，在 DSH 与 Codex 分别开新会话。让 Agent 面对相同的可见能力，人工释放资料时遵循同一意图匹配规则。先记录实际宿主和模型名称，无法选择相同模型时，比较结果属于“宿主与模型组合差异”。

固定一组条件，只变更一个因素。比较旧版/新版项目时固定宿主、模型与材料。比较宿主时尽量固定模型、权限和工具契约。真实平台内容会变化，动态探索的可重复比较优先用本页合成材料，浏览器连接另行检查。保留原样输入和额外提示次数，不能只对失败的一侧追加指导。

按失败出现的位置判断下一步。

- 可用目录里没有目标工具，先查宿主发现/配置，记录缺少哪项能力。
- Skill 已加载但命令、连接或读取失败，记录实际命令状态与页面错误，再查执行链。
- 正文已返回但遗漏评论或新情境，检查方法是否给出了明确转向条件，以及 Agent 是否运用了该条。
- 单项能完成、长任务中丢掉原问题或执行状态，检查压缩后的上下文与任务记录恢复。
- 在多个模型上稳定漏掉同一方法触发，优先修项目规则。单次失败只能证明该次组合失败，不能直接归咎模型或 Harness。

这些记录用于定位改动方向，不要求建设新的调度器或多 Agent 框架。实际运行与当前验证边界由 [V2 升级记录](../docs/v2-review.md) 登记。
